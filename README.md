# IC2：新纪元 / IC2: New Era

**IC2-newera 是基于 IC2 Classic、Create（机械动力）与 ProjectE（等价交换）开发的 Minecraft 1.19.2 Forge 工业附属模组。** 项目在现有工业设备与物流体系上扩展现代材料、电子中间体、工业数据网络、控制服务器、终端机和中文 AI 助手，以统一工艺路线连接工业生产与可审阅的控制操作。Mod ID：`ic2newera`。

当前为开发测试版本 `0.1.0-dev`。服务器设备列表与运行诊断 AI 已构建并安装，包含 EU 电动机、三档权限和 WiFi 增幅器。本次完整更新清单见[玩家包更新说明](docs/player-update-2026-10-08.md)，构建与安装证据见[阶段交付记录](docs/server-device-list-delivery-2026-10-08.md)；游戏运行、多人权限与外部模型调用仍待实机验收。

## 三个基础模组如何协作

| 模组 | 在项目中的职责 |
| --- | --- |
| [IC2 Classic](https://www.curseforge.com/minecraft/mc-mods/ic2-classic/files/8545995) | EU 能源、电网、储能、既有粉碎和高级冶炼设备、工业部件与物流 |
| [Create / 机械动力](https://www.curseforge.com/minecraft/mc-mods/create/files/5797604) | 转速传动、机械加工、水洗、输送、分拣和机械自动化；提供锌与黄铜等原生材料 |
| [ProjectE / 等价交换](https://www.curseforge.com/minecraft/mc-mods/projecte/files/4860858) | 可选兼容；暗物质是终端机合成的必需原料，测试整合包包含此模组 |
| IC2：新纪元 | 批准工艺路线、新增矿物和电子材料、工业网络、生产规划、终端规则和中文助手 |

EU 和 Create 转速保持各自体系；唯一能源方向转换由电动机从 EU 输出到 Create 轴系，不反向发电。物品和流体使用已有运输设施；新纪元的光纤与 WiFi 只传状态和控制数据。ProjectE 未安装时不加载终端机的暗物质配方，也没有省略暗物质的替代配方。

## 当前内容

### 矿物、合金与统一工艺

新增镍、铬、钛、钨四种矿物，受控阶段为原料、含杂质粉、清洁粉和成品金属。粉碎产出的含杂质粉需要经过 Create 水洗；镍、铬可普通熔炼，钛、钨使用已核实的 IC2 高级炉路线。项目另有六种合金及相关装备。

`ProcessGraph` 是批准工业路线的统一数据源，当前包含 54 条路线；配方生成、RecipeGuard、生产规划、AI 受控材料建议、科研、BOM、JEI 和工业服务器共用这些路线。RecipeGuard 精确阻止未授权的阶段跳跃，保留允许的原矿单倍早期熔炼。复杂化学、电解、浸出、酸液与催化路线已退出当前开发范围。

### 电子中间体与两台处理机

电子路线包含硅、高纯硅、PCB、集成电路、CPU、RAM、GPU 和工业固态硬盘，硅原料来自下界石英。服务器配方必须使用 CPU、RAM 和工业 SSD；工业 AI 核心必须使用 GPU。这些是实际合成中间体，不模拟真实硬件的性能参数。

新增材料加工设备为非金属处理机和电子材料加工机。其余适用工序复用 IC2 Classic/Create 现有设备；网络与控制设备另行提供。

### 单向 EU→Create 电动机

`ic2newera:eu_motor` 只把 IC2 EU 转成 Create 轴系动力，不反向发电。界面默认 64 RPM，可选 32/64/128 RPM，对应 1024/2048/4096 SU 与固定 10/20/40 EU/t（128 RPM 需持续提供 40 EU/t 总供给）；缓冲 10000 EU，从背面接收 LV 包（每包最多 32 EU）。初次启动需缓冲具备当前档位 20 tick 额定用电量；缺电停机后要等待 20 tick 且缓冲够量才重启。UI 可反转与启停；轴系已有其他 Create 动力源时，电动机优先使用外源，本机零发力、零耗 EU。源码已实现，增量离线构建成功，最终构建与安装状态见本阶段交付记录，实机验收待完成。

### 工业网络与控制服务器

交换机自带光纤与 WiFi，正常使用只需放置并填写网络名。默认 WiFi 覆盖是 16 格球形范围；单个升级槽安装 `ic2newera:wifi_amplifier` 后扩为水平 40×40 格（相对交换机 `dx,dz ∈ [-20,19]`），垂直仍各为 16 格。升级不可叠加或串联。适配器靠近机器自动识别并加入附近有权限的网络；服务器和终端机也自动连接，光纤优先。跨区域网络由交换机之间的光纤连接，不要求玩家设置 IP、网关或无线密码。

服务器 GUI 只提供“概览”和“联网设备”两页，不显示工艺流程或材料信息。概览显示设备总数、运行数和异常数；设备页每页 3 台，设备显示编号，列出名称、连接方式和状态，不显示坐标。名单只收录装有机器网络适配器并经 WiFi/光纤联网，或通过实际相邻工业光纤直连的设备。玩家靠近服务器 8 格内可从设备行启动/停止目标；远端目标必须仍已加载、处于同网、实体身份未变且实现 `ControllableMachine`。三档权限约束运行配置、控制和 AI 提案确认：模式 0 root/授权名单可配置、模式 1 所有人可配置但不可授权或切换权限、模式 2 仅 root；只有 root 可切换模式，`grant`、`revoke`、`controller_status` 由 root 或控制台使用。单人/LAN root 为 Minecraft 识别的世界所有者；专用服务器用控制台或权限等级 4 的 RCON 执行 `/ic2newera bind_controller <player>`，将在线 GameProfile 的 UUID 持久绑定。未绑定时无人可更改默认只读模式。所有玩家均可从服务器打开 AI 做只读诊断；快照与联网设备名单一致，优先列出最多 16 台设备（异常优先），并给出设备总数以及未知、空闲、暂停、故障各自数量。只有当前有配置权的玩家能确认 AI 提案。终端库存与规则继续独立按 Owner UUID、队伍或管理员权限保护；服务器配置开放不等于开放他人库存。

### 终端机：144 格库存与物料进出规则

终端机为一个标准方块内的箱式机器，使用深色金属外壳、青色屏幕、紫色数据端口、光纤接口和天线等赛博科技元素。物品中文名称就是“终端机”，没有额外物品描述。

- 容量 **12×12，共 144 格**；为适配小窗口，界面按 12 列×3 行分四页显示。
- 六个方向分别选择输入、输出、双向或关闭；每面有 9 项物品白名单、0–9216 的保留量及 1–64 个物品/秒的托管主动搬运上限。
- 默认上面与侧面输入、底面输出；独立存取及漏斗/管道访问不依赖模型 API。
- 接入同网服务器、安装工业 AI 核心并启用控制与托管后，按保存的规则搬运相邻公开物品接口。
- 光纤/WiFi 不搬运物料，跨距离物流仍通过既有管道、漏斗和传送带完成。

终端机采用 3×3 无序合成，下列原料各 1 个：**箱子、PCB、集成电路、CPU、GPU、工业 SSD、工业光纤、Create 黄铜机壳、ProjectE 暗物质**。详见[终端机设计与操作指南](docs/terminal-design-and-guide.md)。

### 中文 AI 助手与多人操作

普通助手可查询已安装模组的版本、注册 ID、配方及公开文档，提供可核对的资料来源。工业服务器入口另外提供联网设备只读诊断和终端规则提案。AI 生成的提案必须由具备当前配置权的玩家确认，服务端再复查权限、网络、设备身份、设置版本和有效期；提案有效 1800 个游戏 tick，且只能使用一次。

工业服务器由上述三档模式控制配置权；所有玩家可查看，但服务器参数/规划/控制的修改权按模式判定。模式授权不替代终端机 Owner UUID、当前 scoreboard 队伍和管理员对终端库存及规则的独立校验，同名网络也不授予权限。API Key 保留在玩家本机模型配置中，不交给游戏服务器；共享包不带任何玩家模型配置。多人设置、使用与排查步骤见[玩家指南](docs/new-industrial-stage-guide.md)和[助手设置](docs/ai-assistant-setup.md)。

## 源码项目与构建

仓库和完整项目压缩包均沿用原文件夹名 **IC2-newera**。下载[完整项目 ZIP](dist/IC2-newera.zip)后，顶层目录为 `IC2-newera/`；源码、资源、文档、资源生成脚本、Gradle Wrapper、当前自有 JAR 与测试包一起保留。开发缓存、玩家运行目录、私有配置、安装备份、日志及来源未核实的旧参考图不进入公开交付。

```powershell
git clone https://github.com/jiuxiansheng1111/IC2-newera.git
cd IC2-newera
.\gradlew.bat build -x test
```

需要 JDK 17。新环境首次构建需联网下载 ForgeGradle、Minecraft 与模组依赖，已有完整缓存时可以加 `--offline`。输出在 `build/libs/`。本项目交付约定不新增或运行测试，`-x test` 保持这一约定；构建通过与实机验收分开记录。清理构建前应保存 `build/deployment/` 安装回执和备份。

| 目录 | 内容 |
| --- | --- |
| `src/main/java/` | 模组源码、流程裁决、网络、机器、界面和助手 |
| `src/main/resources/` | 配方、流程图、中文翻译、模型、贴图和随包资料 |
| `art/` | 原创资源生成脚本、预览及模型索引 |
| `docs/` | 当前规范、玩家指南、兼容审计与阶段交付证据 |
| `scripts/` | 资源/流程更新、PCL 安装、整合包与源码包导出 |
| `releases/` | 当前可分享的新纪元 JAR 与哈希 |
| `dist/` | 四核心测试包、中文说明及完整项目 ZIP |

`scripts/runtime-mods.json` 固定安装源与哈希。PCL 安装脚本面向已配置隔离的 1.19.2/Forge 43.5.0 实例，运行前需关闭该实例；它不是第三方模组下载器。导出整合包脚本依赖运行锁定清单和本机 Gradle 原始依赖缓存，普通玩家使用已生成的 ZIP 即可。
