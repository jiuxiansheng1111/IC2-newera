# 新工业阶段玩家指南

本指南说明源码当前定义的矿物路线、两台加工机、电子材料与工业网络的使用方式。最终可用内容以构建包和游戏内配方为准；本阶段的构建、安装及实机验收由主智能体统一完成后再确认。

## 查配方与数量

唯一工业路线数量来源是 [`process_graph/main.json`](../src/main/resources/data/ic2newera/process_graph/main.json)；生产规划器从服务器同步的这份数据计算材料需求。本文只讲路线用途和设备操作，不重复抄写每条配方的材料数量。制作或加工时，请在游戏内 JEI 查看当前输入数量和结果；服务器规划结果也来自同一 ProcessGraph。若显示配方与路线图不一致，应先修正同一份图和它的读者，不要另维护一份 BOM。

配方阶段标注有 `LEGACY_PROCESS`、`APPROVED_INDUSTRIAL_PROCESS`、`BLOCKED_BYPASS`。旧路线是否保留或封锁由 ProcessGraph 与 RecipeGuard 的实际规则决定；请按 JEI 当前生效结果操作，不要将旧教程中的捷径视作受控工业路线。

## 已有矿物打粉与清洗

铁、金、铜、煤、钻石、石英、锡、银、铝、锌已纳入同一工艺图。矿石（含已有深层/下界变体）、粗金属和旧 Create 粉碎矿先由 IC2 粉碎机或 Create 粉碎轮加工为“含杂质的 X 粉”，再用 Create 风扇加水清洗，得到已有普通粉。铁/金/铜/煤/钻石/锡/银/铝复用 IC2 粉末，石英/锌复用项目已有粉末，不注册另一套净粉。

钻石粉是目标版本 IC2 已有的 `ic2:dust_diamond`。煤块状资源、钻石和石英晶体的打粉也先产生杂质粉，但它们原本的燃料、合成和装备用途照常使用。煤、钻石、石英水洗得到普通粉后，继续走各自用途，不增加成锭或从粉返还宝石的配方。红石粉保持原有流程；青金石、绿宝石、远古残骸和铀没有对应普通粉末，未添加打粉/清洗路线。

每份矿石/粗金属产两份杂质粉；已有 Create 碎矿和煤/钻石/石英固体原料只一比一打粉，避免重复增产。每份杂质粉水洗得到一份普通粉。金属原矿单倍直烧保留早期路线；正常金属粉按批准熔炼路线成锭，金属锭回收一比一得到普通粉。未受控材料继续使用原模组配方。具体输入与批量以 ProcessGraph/JEI 为准。

## 四种核心矿物

镍、铬、钛和钨共享“矿石 → 含杂质粉 → 洁净粉 → 金属锭”的受控路线。先用 IC2 粉碎机或 Create 粉碎轮处理矿石，产物是含杂质粉。使用 Create 风扇的水洗（Splashing）处理该粉末，得到对应洁净粉。普通粉和含杂质粉名称相似，查看物品名称与 JEI 配方确认阶段。

镍粉、铬粉可走普通熔炼路线。钛粉和钨粉的批准工业路线使用 IC2 电力高炉 `ic2:electric_blast_furnace` 或感应高炉 `ic2:blast_induction_furnace`；普通电炉和原版熔炉不承担这两种洁净粉的工业精炼。矿石级旧路线由当前规则标为 legacy，是否在当前包中保留以 JEI/RecipeGuard 最终检查为准。

IC2 和 Create 负责各自机器、能源与传动。Create 风扇/粉碎轮使用转速和机械网络；IC2 机器使用 EU。工业网络不会转换 EU、转速，也不输送物品或流体。

## 高低碳钢

高低碳钢各有钢粉、钢锭两种材料形态，不再制作钢坯。先把铁和煤分别通过已有粉碎路线变成普通铁粉和 IC2 煤粉，再放入 IC2 合金炉 `ic2:alloy_smelter` 的两个输入槽，按批准比例加工成对应钢粉。输入数量及批次产量由 ProcessGraph 生成的 JEI 配方显示。

钢粉可在熔炉、IC2 电炉或原版高炉中直接熔成对应钢锭。锭用 IC2 粉碎机或 Create 粉碎轮回收时，只得到同等级钢粉，按一锭一粉，不返还煤粉、不改变高低碳等级。装备配方和维修继续使用对应钢锭，现有英文注册 ID 保留，中文显示改为低碳钢和高碳钢。

全部 13 种新纪元锭（包括旧锭）使用与原版铁锭完全相同的模型比例、16×16 贴图轮廓和明暗位置，仅更换材质颜色。22 种自有粉末使用玩家指定的尖顶颗粒堆；低碳为浅银灰、高碳为深蓝灰。含杂质粉保留深色颗粒，均须按矿物路线水洗；已经配好的合金钢粉直接熔炼。IC2/Create 原有外观保持不变。

## 金属合金统一加工

青铜、黄铜、铝青铜、六种新增合金及高低碳钢的配料统一使用 IC2 合金炉。青铜可将铜粉与锡粉加工为青铜粉，也可将铜锭与锡锭加工为青铜锭；青铜粉再普通熔炼成锭。钢粉工作台配方与 Create 搅拌替代已删除，IC2 原有铜锡混粉工作台配方及 Create 黄铜混料旁路由 RecipeGuard 移除。

已经制成的青铜粉块、青铜块、黄铜块/粒仍可按批准配方拆回原材料；这类存储拆分没有加入新金属。成品锭打粉只回收同一种合金。装备工作台配方继续使用对应合金锭。

## EU 与 Create 动力转换

初级与高级 EU 电动机把 IC2 EU 转为 Create 轴动力；初级与高级机械发电机消耗 Create 应力和转速产生 EU。四台机器均为独立物品，配方以 ProcessGraph 和 JEI 为准。前端接 Create 轴，后端接 IC2 电缆；工业光纤只传数据。初级电动机最高收二级包，高级最高收四级，低等级电源也能供高等级机器，但功率不足会停机。

初级电动机 32/64/128 RPM 时分别提供 1024/2048/4096 SU，消耗 10/20/40 EU/t；高级 64/128/256 RPM 分别提供 32768/65536/131072 SU，消耗 320/640/1280 EU/t。电动机缓冲需先积累20刻额定电量才启动；缺电会停机，轴上其他动力源优先。发电机在128 RPM时，初级消耗2048 SU生成16 EU/t，高级消耗65536 SU生成512 EU/t；256 RPM时数值加倍。初级输出电压上限可设一级/二级，高级可设一级至四级；实际输电受电压、存储和轴网影响。机械过载、缺转速、红石信号、存储已满或关闭应力系统时不发电；满电和红石停机时仍消耗机械应力。以上为源码行为，待游戏内验收。

## 按外形辨认设备

终端机是有青紫灯带的宽屏操作台，键盘台下方可辨认物料接口；背面为数据端口与无线结构。工业控制服务器是黑色机柜，前面为分层硬盘托架，背面可见风扇、数据端口与布线槽。

非金属处理机采用米黄色机身和顶部敞口粉料斗；电子材料加工机采用白色机架和蓝色观察舱。机器网络适配器是小型青色天线模块，工业交换机是双天线的低矮多端口机箱，EU 电动机可凭铜色绕组和输出轴承辨认。连接与加工仍按各设备界面说明操作。

## 两台处理机和设备槽位

### 非金属处理机

非金属处理机用于下界石英粉制硅、硅制高纯硅。先用 IC2 粉碎机或 Create 粉碎轮加工下界石英，取得含杂质的石英粉；Create 水洗得到已有石英粉后，再将配方所需材料放入输入槽，等待机器输出硅或高纯硅。

机器界面有一个输入槽和一个产物槽。输入槽仅接受当前已登记配方在此位置要求的物品；产物槽只能取出机器输出，不能回填。

### 电子材料加工机

电子材料加工机制作 PCB、集成电路、CPU、RAM、GPU 和工业固态硬盘。它有六个按配方位置对应的输入槽和一个产物槽；配方输入顺序固定，材料必须放入正确输入槽。每个输入槽只接受对应注册配方在该槽要求的物品，最后从产物槽取货。

两台机器的槽位提示与服务端 `mayPlace` 规则共用当前配方校验。对自动化而言，输入可从非底面进入，产物由底面输出；具体物品过滤仍由服务端当前配方决定。查看槽位悬停提示，并按 JEI 中的配方位置装料。

用 IC2 电缆向两台机器供给 EU，连接侧面、后面、顶部或底部；正面不接收 EU。缓冲容量为 4096 EU，超出 IC2 第三级电压上限的能量包会被拒收。先确认界面出现 EU 储量，再按 JEI 的固定输入位置放料。悬停输入槽会列出该位置允许的原料，输出槽只取出。缺料、输出已满或供电不足会显示对应状态。电子材料加工机的装配配方使用 IC2 基础电路与 Create 电子管，不需要先在这台机器里生产电路板。

方块模型保持一个标准方块空间内。两台加工机外形不同：非金属款有粉料入口与底部托盘，电子加工机有独立芯片观察窗。模型、像素纹理与资源路径约定见 [`models-and-slot-guidelines.md`](models-and-slot-guidelines.md)。

## 九种电子材料

电子线以原版下界石英为硅来源，不新增硅矿。IC2 粉碎机或 Create 粉碎轮把石英加工成含杂质的石英粉，Create 水洗成普通石英粉；非金属处理机继续加工为硅和高纯硅。电子材料加工机再按 JEI/ProcessGraph 制作：

- 石英粉、硅、高纯硅：非金属原料和半导体材料。
- PCB、集成电路：后续电子模块的基板和芯片。
- CPU、RAM、GPU、工业固态硬盘：服务器和 AI 核心使用的功能模块。

IC2 Classic 已有的电路继续复用；服务器配方还使用 `ic2:machine_block`。当前 IC2 Classic 2.1.3.4 的 registry ID 是 `ic2:circuit`、`ic2:advanced_circuit` 和 `ic2:complex_circuit`；不要注册新纪元同功能的 IC2 电路副本。Create 的电子管、精密构件也继续使用 Create 自有物品。精确输入、数量与产物以 ProcessGraph 和运行时配方为准。

## 工业网络搭建

### 建立网络

1. 放置工业网络交换机。右键可查看状态；网络名初始为 `Factory`。要组成同一有线网络，交换机使用相同网络名，并按交换机自身权限管理网络设置。
2. 将机器网络适配器贴近一个受支持机器放置。适配器扫描与它相邻的方块实体；最多列出六个可识别设备。IC2 设备读取其公开状态，Create 动力方块读取转速和过载状态；只有实现项目 `ControllableMachine` 的机器才具备本项目的启动/暂停控制入口。
3. 适配器会自动加入符合权限的最近交换机。普通 WiFi 范围为以交换机为中心的 16 格球形范围；装入 WiFi 增幅器后，水平范围扩为 40×40 格，即相对交换机的 `dx`、`dz` 分别为 -20 至 19，上下仍各为 16 格。若交换机旁接有工业光纤，则沿连续相邻光纤优先建立有线链路。
4. 用工业光纤把交换机连成相邻方块链。光纤只传工业网络数据，不传 EU、转速、物品或流体。拓扑扫描有界：最多追踪 256 段光纤、32 台交换机和 128 个适配器；超过范围的设备不会纳入该次网络视图。

### WiFi 增幅器

`ic2newera:wifi_amplifier` 是交换机使用的升级物品，不是独立方块。一个交换机只有一个升级槽，安装一个增幅器后无线数据范围在水平方向扩到 `dx,dz ∈ [-20,19]`（40×40 格），上下仍各为 16 格。增幅器不可串联或叠加，不扩大物品物流范围，也不传 EU 或 Create 转速。ProcessGraph 配方使用现有 `ic2newera:pcb` ×1、`ic2:circuit` ×1、`ic2:copper_insulated_cable_item` ×2、`create:electron_tube` ×2、`create:andesite_alloy` ×3，不注册安山合金副本；源码已实现，增量离线构建成功，最终构建与安装状态见[本阶段交付记录](motor-wifi-access-delivery-2026-10-08.md)，实机验收待完成。

交换机状态页显示网络名称与有线交换机数量。服务器 GUI 仅有“概览”和“联网设备”两页：所有玩家可查看设备总数、运行数、异常数及设备列表；列表每页 3 台，使用稳定编号显示名称、连接方式和状态，不显示坐标。名单只统计装有机器网络适配器并通过 WiFi/光纤联网的设备，以及通过实际相邻工业光纤直连的设备。AI 读取同一名单与故障状态。适配器状态页显示自动选择的交换机、连接方式、识别到的设备及状态。若显示未连接，先核对距离、相邻方块链、交换机网络名和成员权限。

### 控制服务器与 AI 核心

放置工业控制服务器，使其位于交换机 Wi-Fi 范围或相邻光纤网络中。所有玩家都能打开服务器查看状态与当前信息。GUI 旁的三档权限开关控制服务器运行设置、规划与机器控制的修改权限：

| 模式 | 谁能查看/诊断 | 谁能改运行参数、控制设备和确认 AI 提案 |
| --- | --- | --- |
| 0：所有人查看（默认） | 所有人 | root 房主及已授权名单 |
| 1：所有人配置 | 所有人 | 所有人；不能改权限、切换模式或授权他人 |
| 2：仅房主配置 | 所有人 | 仅 root 房主；授权名单在此模式不生效 |

只有 root 房主可以切换模式。`grant`、`revoke`、`controller_status` 可由 root 或服务器控制台使用；授权名单中的玩家只能在模式 0 下改服务器运行设置，不能授权其他玩家。在模式 0 和模式 2 中，普通 OP、服务器方块放置者和同队关系本身都不会赋予服务器修改权限；模式 1 则向所有玩家开放运行设置。

单人及局域网世界的 root 是 Minecraft 识别的单人世界所有者。专用服务器通过控制台或权限等级 4 的 RCON 执行 `/ic2newera bind_controller <player>`，按在线玩家的 GameProfile 解析并持久绑定唯一服主 UUID。未绑定时处于默认模式 0，所有玩家只读，也没有 root 可以切换模式；普通 OP 不能自行绑定。服务器状态查看不会开放其他玩家的终端库存。终端机库存与规则仍独立沿用终端机自身 Owner UUID、当前队伍或管理员权限。

所有玩家都能从服务器打开 AI 做只读诊断，查询同一份联网设备名单和故障状态。AI 快照优先包含最多 16 台设备（异常优先），附设备总数以及未知、空闲、暂停、故障各自数量；设备以编号识别。AI 提案的确认权沿用服务器三档配置模式：模式 0 为 root/授权名单，模式 1 为所有人，模式 2 仅 root。授权名单只在模式 0 生效；读状态不开放他人终端库存，确认提案仍检查终端自身权限。

三档权限保留；服务器设备列表与 AI 只读诊断源码已实现。构建、安装和验收状态以后续[服务器设备列表交付记录](server-device-list-delivery-2026-10-08.md)为准。

ProcessGraph 规划后端和 AI 规划仍可使用批准路线估算原料、所需机器与工序批次；服务器 GUI 不展示流程或材料，也不提供规划页。操作无需输入坐标：在服务器 8 格内，从“联网设备”页选择目标行启动/停止。目标可在远处，但必须实际已加载、仍连接同一网络、方块实体身份未变且实现 `ControllableMachine`；否则服务器拒绝操作。自动控制只作用于联网设备名单中实现受控接口的机器，并按机器状态尝试暂停或恢复。服务器不要求配置 IP、网关、端口、DNS、密码、信道或硬件参数。

自动控制只作用于适配器已识别且实现受控接口的机器，并按机器报告的缺输入、输出已满、缺电、低功率、过载、离线、禁用或错误状态尝试暂停/恢复。状态读取或控制 API 未实现的第三方机器不会因此变成可控机器；不要把网络设备理解为通用遥控器。

## 玩家与实现边界

- 本指南中配方材料数量唯一来源是 ProcessGraph。配方 JSON、JEI、生产规划器和 AI/服务器说明都应读取这份路线，不复制独立配方表。
- 机器槽位仅接受服务端当前登记配方要求的输入；界面说明不能放宽服务器准入。
- 工业网络是数据层；IC2 EU 和 Create 转速仍各自独立。
- 本地 JAR 静态检查、资源文件存在或源码实现不能代替构建成功、模组加载和玩家实机验收。构建及安装状态由主智能体在交付记录中确认。


旧 PCL 安装记录对应先前包体，不能作为新工业阶段已安装或实机验收的证据。

## 终端机存取

终端机的设计与阶段状态见[设计与操作指南](terminal-design-and-guide.md)。终端机具有 144 格容量，界面每页显示 12 列×3 行，共 4 页，容量等价于 12×12 格。终端机不加工物品，只与直接相邻的 Forge 物品接口存取；相邻另一台终端机不会被 AI 托管主动搬运直接连接，两台终端机可以通过既有漏斗或管道衔接。物品通过现有物流设备搬运，工业光纤/WiFi传递数据。

终端机和既有服务器 AI 提案已实现并通过离线构建，安装版本以交付回执为准，实机效果仍需验收；本阶段服务器权限模式更新状态另由主智能体报告确认。放下即用：上面和四个侧面输入，底面输出。每面可设输入、输出、双向或关闭；每面最多 9 个白名单幽灵物品槽，全部为空才允许所有类型。按物品类型和方向设置 0 至 9216 留存量：纯输入面不以此值设输入目标；输出面用作最低留存；双向面用作拉取目标，也用作最低输出留存。每面每秒 1 至 64 个物品的速率上限只约束 AI 托管主动搬运。漏斗、管道等既有物流设备的被动插入/抽取按其自身速度工作。

## 工业服务器与玩家本机 AI

玩家在普通助手界面中使用当前玩家本机已有的 `LLMConfig`。API Key 留在本机，不发送给游戏服务器。所有玩家可从工业服务器打开 AI 做只读诊断，设备状态快照与联网设备名单一致，异常优先、最多 16 台，并附总数及未知、空闲、暂停、故障分类。服务器控制操作仍按三档配置模式授权；只有当前有配置权者能确认提案。终端机库存摘要最多含 8 台终端机、每台最多 12 种物品，并按终端自身权限过滤；快照不代表全厂库存，其他模组控制保持只读。

从游戏内操作 AI：任何玩家均可右键工业控制服务器，选择“AI 助手”进行只读诊断；所有人配置模式下所有玩家可确认提案，默认模式下 root/授权名单可确认，仅房主模式下只有 root 可确认。入口使用该玩家本机已保存的模型设置，API Key 留在本机，不上传服务器。终端库存快照仍按终端自身权限过滤，不代表全厂库存。普通按 I 打开的助手不会自动扫描工厂，也不会自动获得服务器快照。

按当前服务器权限模式获准的玩家可在服务器右侧槽位安装工业 AI 核心并启用控制；终端机自身的 AI 托管与接口面规则仍按该终端机 Owner UUID、当前队伍或管理员权限管理。获准的服务器 AI 助手可提出终端机规则，玩家点击“审阅终端提案”检查内容并确认，再执行。服务器只应用尚未过期且通过服务器模式、终端可访问性、当前网络、终端设置版本与终端机/服务器方块实体身份复查的一次性提案；即使终端机或服务器在原位置拆除后重放，旧提案也会失效。提案有效期为 90 秒（1800 个游戏 tick）。执行结果会显示在游戏聊天中。

AI 托管主动搬运在游戏服务器本地运行，不依赖模型 API；需处于可访问的同一网络、服务器装有 AI 核心、控制已启用且终端机 AI 托管已开启。服务器模式不会取消终端 Owner/队伍权限或公开其他玩家的库存。终端搬运功能源码已离线构建；本阶段服务器权限更新的构建、安装和实机状态以主智能体交付报告为准。

## 终端机多人使用

工业控制服务器按 GUI 三档权限模式开放修改；单人/LAN root 或专服绑定服主可切换模式并管理授权名单，未绑定的专用服务器保持默认模式 0 的只读状态。模式 1 只开放工业服务器自身的运行参数、规划和控制，不会公开其他玩家的终端库存、菜单或物品。

终端机库存与规则独立按终端机 Owner UUID、当前 scoreboard 队伍成员或管理员授权，不受服务器三档模式改变。管理员可建立队伍并管理成员，例如 `/team add 工厂`，随后用 `/team join 工厂 玩家` 让玩家加入（需有相应命令权限）。同队成员可按终端机既有权限配置终端机或访问库存；离队后队伍权限撤销。每次终端菜单操作、库存访问和 AI 提案应用均须服务端校验；终端机直接拆除也需要管理权限。服务器权限更新的源码状态由主智能体交付报告确认，实机仍待验收。

## 终端机配方与可选 ProjectE

设计配方为 3×3 无序配方，九种材料各一份：`minecraft:chest`、`ic2newera:pcb`、`ic2newera:integrated_circuit`、`ic2newera:cpu`、`ic2newera:gpu`、`ic2newera:industrial_ssd`、`ic2newera:industrial_fiber`、`create:brass_casing`、`projecte:dark_matter`。九种原料 ID 已与当前 ProcessGraph 声明匹配；暗物质 ID 已按当前安装的 ProjectE 原生配方核实。电子材料复用现有真实合成物品；终端机不引入额外一批电子物品。

ProjectE 可选。未安装时不加载暗物质配方和相关批准路线，也没有不含暗物质的替代配方。服务器继续需要 CPU/RAM/工业固态硬盘，AI 核心继续需要 GPU。终端机已通过离线构建，实际安装版本以交付回执为准，实机仍待验收。


## 服务器与助手界面操作

服务器右侧 AI 核心槽独立显示，悬停空槽或已放核心时只显示一份中文槽位说明。服务器和助手使用 Minecraft 的 GUI 坐标；普通 320×240 及更大的 GUI 中按钮、背包和聊天输入区完整显示。AI 助手不暂停单人世界，服务器查询可继续处理。聊天页的长状态和资料发送说明可悬停查看完整内容，切换窗口大小保留草稿及正在进行的请求；关闭助手取消当前请求。

终端机物品仅命名为“终端机”，不附加新纪元自定义物品描述。仓储和过滤规则的操作说明保留在机器界面及本指南。

网络发现和状态说明：计数为已加载、已发现的联网设备，发现范围上限为32台交换机、256段光纤、128台网卡，每次索引最多256个候选，终端计数最多32台。AI机器样本最多16台且异常优先；超过采样范围时不能声称排查了全厂。运行数读取公开活动/转速或受控接口；第三方设备未提供活动状态时显示未知，普通待机与手动暂停不计为故障。原生IC2/Create未提供的缺料、输出堵塞原因不能推测。只读查询不会触发机器启停。
