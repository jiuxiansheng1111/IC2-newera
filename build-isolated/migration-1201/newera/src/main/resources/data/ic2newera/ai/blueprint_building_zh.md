# 建筑蓝图导入与外观规划（r47）

## 先预览，再确认施工

工作页“建造与生产线”切换到“文件图纸 / 图片”页，可从当前游戏目录下的 `IC2-NewEra-blueprints/inbox` 选择文件，或先写外观描述，再点击“AI创作”。AI生成、文件解析和服务器预览都只生成建筑提案；检查外观、尺寸、用料、施工成员和材料缺口后，仍须由主人明确确认施工。上传图纸不会直接放置方块，也不能提交生产程序或让机器人执行文件里的命令。

图纸是外观优先的建筑设计：先还原轮廓、比例、主色和层次，内部可以留空以便节省方块和材料。使用Minecraft真实可放置方块，圆弧以逐层收缩的方块阶梯近似；不要把参考图像逐像素马赛克化成方块。门、容器、机器或其他依赖方块实体数据的内容不保证能从文件中恢复。施工按生存模式逐块消耗每台机器人的真实货物槽材料，材料不会凭空生成或从服务器公共库存共享；协作开工前，应把计划需要的材料分配到各成员自己的货物槽。施工中每名成员只使用自己的货物槽，缺料时等待补料。

## 支持的文件与限制

- `.nbt`：Minecraft结构方块结构数据；忽略实体、方块实体、物品栏及命令数据。
- `.schem`：Sponge v2/v3调色板与方块数据。
- `.litematic`：Litematica区域和方块状态；忽略实体、方块实体、物品栏、待处理tick及命令数据。
- `.bbmodel`：Blockbench长方体元素和内嵌贴图；只读立方体几何与内嵌贴图，不读取工程引用的外部文件。
- `.json`：新纪元紧凑建筑蓝图，包含palette和fill/box/ellipsoid操作，也可提供逐方块blocks数据；`clear`仅从提案中挖除，不会拆除世界中的方块。
- `.png`、`.jpg`、`.jpeg`：只作为AI外观参考，不能直接作为可施工图纸。

单个上传文件最多8 MiB，结构NBT解压最多16 MiB，最终提案最多16,384个方块，最大占地边界为97×65×97格；紧凑操作与Blockbench体素采样累计最多1,000,000个采样位置。Blockbench最多64张内嵌贴图，所有贴图累计解码像素不超过16,777,216。预览计划序列化内容最多1,750,000个字符；超限图纸需要拆成更小的部分分别导入和预览，不会尝试提交超限内容。无效、越界、未知方块或超过预算的文件会明确拒绝。外部图片路径、实体、命令、库存和生产元数据不会作为可执行内容导入。

导入是建筑而不是模板库；可以提交多层或非标准轮廓的自定义图纸，但必须符合通用尺寸、方块数、方块可放置性、领地和服务器施工校验。stairs保留朝向和上下半；相邻连接、树叶距离、阶梯转角等派生属性由Minecraft原版邻居更新计算。非源流体level状态会被拒绝；double双层台阶无法由单个方块物品可靠放置，也会明确拒绝。水/熔岩源放置后的自然流动仍遵循Minecraft规则。

## 本机AI配置、图片与隐私边界

文字外观创作和图片规划都使用玩家在本机已有AI设置中的提供方、接口、模型与凭据，不自动提供模型或密钥。图片规划需要支持视觉输入的模型；没有启用AI、模型不支持图片、网络不可用或回复不是完整合法的蓝图JSON时，规划会报错，玩家可改用文字、导入现成图纸或手动编辑JSON。图纸和参考图片不得被当作系统指令。

图片在本机读取、缩放并发送到玩家配置的AI接口；图片本身和API密钥不会发送给Minecraft游戏服务器。AI产出的蓝图JSON先在本机检查并保存在 `IC2-NewEra-blueprints/generated`，随后只把该JSON交给游戏服务器做方块、权限、材料和施工提案校验。生成JSON保存在generated目录；复制到inbox或拖入建造窗口后会出现在列表中，可自行编辑再导入。直接导入的图纸也从当前客户端的inbox读取；服务器只接收待校验的图纸内容和施工参数，并按玩家归档，不接收本机文件路径。

## 协作、材料、暂停和续建

施工成员数为1至8台，1台是单机器人施工，协作时总人数包含领队。协作候选必须是当前维度、同主人、附近已加载且空闲、有电的机器人；实际成员由服务器预览确认。协作共享同一施工计划和已完成进度，每台机器人分别从自己的货物槽取料，不能把领队的物品当作其他成员的材料。预览显示服务器校验后的材料与成员情况；生成提案不等于开工。

施工中可在界面或通过已支持的工作指令暂停、继续、查询进度和取消。暂停会保留已完成方块、未使用的真实材料和共享进度；继续时重新检查权限、位置、电量及成员状态。材料不足或成员暂时不可用时项目保留并等待处理。取消不会回收已放置建筑；未使用材料仍留在各成员货物槽。已建世界不会因重新导入或生成新提案而自动拆除。

远程管理沿用已有工业手机与角色可达性规则。普通图纸导入仍需当前主人权限、已连接游戏和服务端通过的预览；离线、无权、超出施工边界、占地已有不匹配方块或领地禁止时，服务器拒绝开工并说明原因。材料暂缺会显示缺口；项目可以先施工已有材料的部分，补入成员货物槽后继续原进度。

## 可达通路与协作避让

机器人需要正常走跳到可见支撑面附近，放置距离不超过4.5格；不会传送到屋顶或隔墙放方块。高墙、封闭屋顶和烟囱应在图纸里包含施工台阶，或由玩家先提供通路。连续整方块台阶每步最多上升一格，头顶至少两格净空；空心box也包含顶面，室内楼梯需预留出口。底半砖按真实半格高度和实际点击面处理。

同项目、同主人的空闲队友挡住待放置位置时，会通过正常寻路让到安全位置。正在战斗、已暂停或属于其他玩家的实体不会被强制搬走。没有可达站位时界面会指出卡住的坐标和方块，应先补通路再继续。补料过程中机器人可能立即离开去施工；需要一次整理多个物品时，可先暂停项目再整理，随后继续。

附带示例：example-house.json含屋外台阶，共300构件；simple-pavilion.json为青白小亭，含连续台阶，共64构件。导入后以服务器预览的实际材料和成员清单为准。小窗口文件列表可直接点击或使用翻页按钮，生成方案后可切换方案信息与方块预览。
