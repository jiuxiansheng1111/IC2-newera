# 机器人建筑图纸：玩家操作与文件格式

本页说明机器人“建造与生产线”界面的文字方案、文件导入、图片创作和多人施工流程。导入或 AI 创作首先只生成待确认的建筑提案；只有玩家再点“开始施工”，机器人队伍才会尝试放置方块。外部图纸只允许生成房屋，不会作为生产程序执行，也不会直接修改世界。

## 玩家操作流程

1. 在机器人界面打开“建造与生产线”。在“文字建造”页输入建筑或生产线描述。点“生成方案”会使用游戏服务器上的现有规划器；点“AI创作”会由当前客户端连接的 AI 服务创作外观，再把生成的方块图纸交给服务器校验。改造生产线仍应使用文字方案，外部图纸仅支持房屋。
2. 导入现成文件时，切换到“文件图纸 / 图片”，点“打开图纸目录”。游戏会打开当前实例目录下的 `IC2-NewEra-blueprints/inbox`；把文件复制到该目录后点“刷新”，或把文件直接拖到界面。选择一项后点“解析并预览”。同名拖入文件不会覆盖已有文件。
3. 服务器返回方案后，先查看真实方块预览、材料清单、施工位置和被选中的机器人。拖动预览可旋转，滚轮可缩放。生成预览本身不会开工；核对无误后点“开始施工”。
4. “施工人数”在生成提案前选择 1–8。多人提案会显示实际选中的附近空闲机器人；服务端在预览中锁定成员，开始时会再次核对。可用人数不足时可退回选择较少人数。施工期间用“暂停作业”“继续作业”“检查与进度”管理工作。取消要点两次确认；已放置的方块不会随取消自动拆除。
5. 开工后仍要给施工机器人提供所需方块和能量。缺料或无法到达时任务会等待，补齐材料/通路后继续。远程手机建造仍受现有手机电量、距离和权限限制。

## 文件来源、格式与隐私

当前文件列表和拖放入口接受 `.nbt`、`.schem`、`.litematic`、`.bbmodel`、`.json`、`.png`、`.jpg`、`.jpeg`，单文件最大 8 MiB。PNG/JPG 是参考图片，不会直接变成立方体马赛克；选择图片并点击“解析并预览”后，客户端才调用已配置的视觉模型生成建筑方案。客户端 AI 未启用、模型未选择或模型不支持图片时，操作会明确失败。

图纸文件会经游戏连接上传给服务器解析，服务端只返回待确认的方块方案。参考图片本身不会上传 Minecraft 服务器。图片和文字会按玩家配置发送到对应的 AI 服务；如果配置的是远程 API，资料会发给该远程服务。API 密钥只保存在客户端配置中，不发送给游戏服务器。

本目录的 `example-house.json` 可以直接复制到 `inbox` 后刷新选择，也可以拖进界面。AI 创作生成的 JSON 会在 `IC2-NewEra-blueprints/generated` 保存一份可编辑副本，并自动提交给服务器预览。

## 支持的建筑输入

- **Minecraft 结构方块 `.nbt`**：读取 `size`、方块调色板和坐标。多套调色板只采用第一套。
- **Sponge `.schem`**：支持 v2/v3 调色板与 VarInt 方块数据。
- **Litematica `.litematic`**：读取区域、调色板和紧密位打包的 `BlockStates`；互相重叠的区域不支持。
- **Blockbench `.bbmodel`**：仅支持 cuboid；读取 outliner 父子组、组/方块旋转、inflate 与嵌入式纹理 UV，再采样为 Minecraft 整数方块。最长边超过 48 格时等比例缩小。透明纹理采样点跳过；不会读取外部贴图路径。编辑器颜色编号不是材质颜色，未绑定可读嵌入式纹理的 cuboid 会报错。贴图颜色会近似映射到 Minecraft 混凝土、陶瓦或羊毛颜色。
- **紧凑 JSON v1**：见 `example-house.json`。调色板键可以是语义名称；`ops` 用于生成较大体块，`blocks` 用于补充楼梯、台阶等带方块状态的细节。所有操作最终都采样为实际方块。
- **PNG/JPG**：仅供已配置的视觉模型作为外观参考。生成失败时检查 AI 设置、API 权限、连接和模型视觉能力；不会以图片本身代替施工计划。

暂不支持其他 Sponge 版本、非 cuboid Blockbench 元素和床。未知方块 ID、无效方块状态、禁用/不可放置方块不会静默替换为石头。实体、方块实体、容器物品栏、命令和待处理 tick 数据会忽略。门只提交下半部分，由 Minecraft 放置规则生成上半；缺少匹配下半的门上半会报错。

## 紧凑 JSON v1

可直接导入的完整小屋示例见 [`example-house.json`](example-house.json)。先把它复制到 `IC2-NewEra-blueprints/inbox`，再刷新列表选择。也可复制它作为模板，调整坐标、调色板和操作后用不同文件名保存。

- `palette` 必须是非空对象。值可为完整方块状态字符串，也可用 `{ "block": "minecraft:oak_planks", "properties": { ... } }`；属性名和值都必须受目标方块支持。
- `ops` 最多 512 项。`fill` 和 `box` 的端点包含在范围内；`hollow:true` 只写外壳。`ellipsoid` 在包围盒中采样成阶梯方块；`hollow:true` 只保留壳层。后续操作覆盖前序结果。
- `clear` 仅删除本蓝图先前生成的位置，不表示拆除世界中已有的方块。
- `blocks` 每项可写 `{ "pos": [x,y,z], "palette": "key" }`，也可写 `{ "pos": [x,y,z], "block": "minecraft:oak_stairs[...]" }`。它们在所有 `ops` 后应用，用于细节并覆盖同坐标结果。
- 坐标必须是整数；原始操作坐标范围为 `-4096..4096`。归一化后的建筑不超过 `97×65×97`，即 X/Z `-48..48`、Y `0..64`。
- 只允许 `kind:"house"`。其他类型（包括 `production`）会被拒绝；不能通过 JSON 上传自定义生产程序。

## 资源上限

- 上传文件最多 8 MiB；NBT 解压后最多 16 MiB；结构源体素最多 1,000,000。
- 紧凑 JSON 最多 512 个操作；操作与细节方块累计采样最多 1,000,000 个位置；最终提案最多 16,384 个方块。
- Blockbench 最多 16,384 个模型元素、64 张嵌入贴图；所有贴图的像素总量最多 16,777,216。
- PNG/JPG 最多 32,000,000 像素，送往视觉模型前缩小到最长边不超过 1024 像素；生成的图片编码也有大小限制。
- 普通文字/状态请求的界面等待提示为 15 秒；若超时，服务端操作不会因此撤销，迟到的回复也可能已被界面忽略。先点“检查与进度”确认状态，再考虑重试。
- 图纸上传/解析的客户端等待上限约 125 秒，服务端上传会话约 120 秒过期；超时只表示没有及时收到预览结果，不会自动开始施工。不要连点重复提交。
- AI 请求时长由客户端 AI 设置中的超时控制（1–600 秒）；AI 失败或超时不会开始施工。预览计划 SNBT 序列化上限为 1,750,000 字符；超过上限会在提交预览前拒绝并提示拆分图纸，以兼容施工任务恢复记录大小限制。
