# 机器人高级炉、合金生产线与指定电源

本页记录 2026-10-22 高级炉与合金线的已安装阶段；下文相邻供电是当时布局。用户后续要求共用电缆连接多个设备，新一轮正在实施，不能把本页测试结果当作新接线方案已经实测。

## 操作

在角色“工作 → 建造与生产线”输入描述，检查场地、设备、原料、工序与电源预览，再确认施工。例如：

- `搭建一条锡生产线，用火力发电机供电，产出20个锡锭`
- `搭建钛生产线，用低压太阳能供电，产出10个钛锭`
- `搭建低碳钢生产线，用燃煤发电机供电，产出20个低碳钢锭`
- `搭建钒钢生产线，用低压太阳能供电，产出8个钒钢锭`

不指定产量时持续生产；有限产量按完整配方批次执行，可能略多于请求值。所有多产和中间余料一起存入成品箱。电源型号也可明确写 `ic2:generator` 或 `ic2:solar_panel_lv`。目前支持这两种，未指定时默认火力；不支持的电源会报错，不静默改成其他电源。

## 实际工艺与设备

唯一工艺来源为服务器当前 ProcessGraph。规划器递归展开批准上游：原矿/原料、IC2 粉碎、Create 清洗、普通熔炼、高级电力高炉、合金配料及后续熔炼。受控中间物缺少可用的批准上游时拒绝方案，不把它冒充原料省掉环节。

高级炉使用 IC2 Classic 2.1.3.4 的 `ic2:electric_blast_furnace`，不是原版高炉。合金配料使用 `ic2:alloy_smelter`，没有工作台或 Create 搅拌旁路。机器人在投入前和取出前检查原生配方的真实输入、数量及输出；产物只能由原生设备加工。

IC2 Classic 当前原生高级炉 JSON loader 不会处理这些配方，因此 RecipeGuard 注册9条对应的高级炉原生配方，并同步 JEI 显示；ProcessGraph 仍是规划器的批准路线唯一来源，运行时再次核验实际配方，不用 JEI 或旁路配方冒充批准工艺。对于同优先级的 RAW 供料，优先选择材料定义的 canonical 原矿，再按批准路线粉碎、清洗等加工；只有图中批准路线和实际原生配方都匹配时才会投入。

粉碎机默认 2 EU/t、高级电力高炉 5 EU/t、合金炉 16 EU/t。火力发电机默认 10 EU/t：粉碎机和高级电力高炉各配一台，合金炉两侧各配一台。低压太阳能默认 8 EU/t：同样一台/两台，合金炉合计 16 EU/t。电源与机器直接相邻供电；数值可能受服务器配置影响。

低压太阳能需晴天、白天和天空无遮挡，条件不足时停止继续投入，物料保留。太阳能不耗煤，但线路中的原版熔炉仍需要煤炭/木炭。火力发电机也由机器人从进料箱实际搬运燃料。合金用煤粉是配方原料，不能代替发电机燃料。

## 整齐布局与运输

场站底座 25×9 格。机器排、两格净通道、前排三个箱子分开；同类工序共用一台机器。机器朝北，水洗风扇朝东；水车、清洗水流与围挡采用固定布置。EU 和 Create 转速各自独立，水车只驱动风扇。

相对施工起点：进料箱 `(0,1,-5)`、周转箱 `(12,1,-5)`、成品箱 `(24,1,-5)`。机器人沿通路在真实容器之间搬运，运输不依赖新造的物品管线或虚拟物料。需保留三个空货物格，周转箱及新建机器在开始时应为空。每个周期先备齐原料，再逐工序配料；两种合金原料一起带到炉子旁投入。

施工材料放角色货物槽，可分批补充；运行原料和煤放进料箱。设备需提前制作，本方案不承担全地图采矿、自动合成所有设备或清除场地。已有方块和建筑不自动覆盖。

默认木屋在西侧增加一格宽的实心台阶通道至屋顶，并设置侧入口落脚平台；9×7 主体向西延伸后总占地为12×7，共223个施工部件。机器人可在预定通路受阻时改选站位，最多绕行64格，不强制加载未加载区块。

烧矿任务在明确开始时记录可用原料快照并以此限定本次输入预算，防止把同一任务刚产出的铁锭再次自动烧成精炼铁。暂停、保存和恢复会保留原预算；后来放进角色货物槽的新原料不会自动加入当前批次。若要使用新增原料或再次加工本次产物，请明确重新开始烧矿，以建立新的输入快照。

## 暂停与数据保护

支持暂停、继续、取消；暂停角色不会停止已点燃的原生炉子。正常实体保存记录施工及生产进度、运输物和批次。缺料、堵路、缺电、风向/水流错误、满箱、配方变化、周转箱或暂存格被外部改动时停止推进并给中文原因，不删除实物。取消后机器、箱子和角色中的实物均保留。

内置 AI 的能力说明同步上述范围；模型回复不能替代服务端的施工确认和真实完成状态。旧版生产任务仍按旧记录执行，新规划使用版本2；本次不转换旧世界中的场站。
