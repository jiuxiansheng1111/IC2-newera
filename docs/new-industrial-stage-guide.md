# 新工业阶段玩家指南

本指南说明源码当前定义的四种矿物路线、两台加工机、电子材料与工业网络的使用方式。最终可用内容以构建包和游戏内配方为准；本阶段的构建、安装及实机验收由主智能体统一完成后再确认。

## 查配方与数量

唯一工业路线数量来源是 [`process_graph/main.json`](../src/main/resources/data/ic2newera/process_graph/main.json)。当前文件有 51 条 routes；生产规划器从服务器同步的这份数据计算材料需求。本文只讲路线用途和设备操作，不重复抄写每条配方的材料数量。制作或加工时，请在游戏内 JEI 查看当前输入数量和结果；服务器规划结果也来自同一 ProcessGraph。若显示配方与路线图不一致，应先修正同一份图和它的读者，不要另维护一份 BOM。

配方阶段标注有 `LEGACY_PROCESS`、`APPROVED_INDUSTRIAL_PROCESS`、`BLOCKED_BYPASS`。旧路线是否保留或封锁由 ProcessGraph 与 RecipeGuard 的实际规则决定；请按 JEI 当前生效结果操作，不要将旧教程中的捷径视作受控工业路线。

## 四种核心矿物

镍、铬、钛和钨共享“矿石 → 含杂质粉 → 洁净粉 → 金属锭”的受控路线。先用 IC2 粉碎机或 Create 粉碎轮处理矿石，产物是含杂质粉。使用 Create 风扇的水洗（Splashing）处理该粉末，得到对应洁净粉。普通粉和含杂质粉名称相似，查看物品名称与 JEI 配方确认阶段。

镍粉、铬粉可走普通熔炼路线。钛粉和钨粉的批准工业路线使用 IC2 电力高炉 `ic2:electric_blast_furnace` 或感应高炉 `ic2:blast_induction_furnace`；普通电炉和原版熔炉不承担这两种洁净粉的工业精炼。矿石级旧路线由当前规则标为 legacy，是否在当前包中保留以 JEI/RecipeGuard 最终检查为准。

IC2 和 Create 负责各自机器、能源与传动。Create 风扇/粉碎轮使用转速和机械网络；IC2 机器使用 EU。工业网络不会转换 EU、转速，也不输送物品或流体。

## 两台处理机和设备槽位

### 非金属处理机

非金属处理机用于下界石英粉制硅、硅制高纯硅。先用 IC2 粉碎机或 Create 粉碎轮加工下界石英，取得新纪元石英粉；随后将配方所需材料放入输入槽，等待机器输出硅或高纯硅。

机器界面有一个输入槽和一个产物槽。输入槽仅接受当前已登记配方在此位置要求的物品；产物槽只能取出机器输出，不能回填。

### 电子材料加工机

电子材料加工机制作 PCB、集成电路、CPU、RAM、GPU 和工业固态硬盘。它有六个按配方位置对应的输入槽和一个产物槽；配方输入顺序固定，材料必须放入正确输入槽。每个输入槽只接受对应注册配方在该槽要求的物品，最后从产物槽取货。

两台机器的槽位提示与服务端 `mayPlace` 规则共用当前配方校验。对自动化而言，输入可从非底面进入，产物由底面输出；具体物品过滤仍由服务端当前配方决定。查看槽位悬停提示，并按 JEI 中的配方位置装料。

用 IC2 电缆向两台机器供给 EU，连接侧面、后面、顶部或底部；正面不接收 EU。缓冲容量为 4096 EU，超出 IC2 第三级电压上限的能量包会被拒收。先确认界面出现 EU 储量，再按 JEI 的固定输入位置放料。悬停输入槽会列出该位置允许的原料，输出槽只取出。缺料、输出已满或供电不足会显示对应状态。电子材料加工机的装配配方使用 IC2 基础电路与 Create 电子管，不需要先在这台机器里生产电路板。

方块模型保持一个标准方块空间内。两台加工机外形不同：非金属款有粉料入口与底部托盘，电子加工机有独立芯片观察窗。模型、像素纹理与资源路径约定见 [`models-and-slot-guidelines.md`](models-and-slot-guidelines.md)。

## 九种电子材料

电子线以原版下界石英为硅来源，不新增硅矿。IC2 粉碎机或 Create 粉碎轮把石英加工成石英粉；非金属处理机继续加工为硅和高纯硅。电子材料加工机再按 JEI/ProcessGraph 制作：

- 石英粉、硅、高纯硅：非金属原料和半导体材料。
- PCB、集成电路：后续电子模块的基板和芯片。
- CPU、RAM、GPU、工业固态硬盘：服务器和 AI 核心使用的功能模块。

IC2 Classic 已有的电路继续复用；服务器配方还使用 `ic2:machine_block`。当前 IC2 Classic 2.1.3.4 的 registry ID 是 `ic2:circuit`、`ic2:advanced_circuit` 和 `ic2:complex_circuit`；不要注册新纪元同功能的 IC2 电路副本。Create 的电子管、精密构件也继续使用 Create 自有物品。精确输入、数量与产物以 ProcessGraph 和运行时配方为准。

## 工业网络搭建

### 建立网络

1. 放置工业网络交换机。右键打开状态界面；网络名初始为 `Factory`，由有权管理者设置。要组成同一有线网络，交换机使用相同网络名，并满足同队/所有者权限规则。
2. 将机器网络适配器贴近一个受支持机器放置。适配器扫描与它相邻的方块实体；最多列出六个可识别设备。IC2 设备读取其公开状态，Create 动力方块读取转速和过载状态；只有实现项目 `ControllableMachine` 的机器才具备本项目的启动/暂停控制入口。
3. 适配器会自动加入符合权限的最近交换机。无线连接距离上限为 16 格；若交换机旁接有工业光纤，则沿连续相邻光纤优先建立有线链路。
4. 用工业光纤把交换机连成相邻方块链。光纤只传工业网络数据，不传 EU、转速、物品或流体。拓扑扫描有界：最多追踪 256 段光纤、32 台交换机和 128 个适配器；超过范围的设备不会纳入该次网络视图。

交换机状态页显示网络名称与有线交换机数量；适配器状态页显示自动选择的交换机、连接方式、识别到的设备及状态。若显示未连接，先核对距离、相邻方块链、交换机网络名和成员权限。

### 控制服务器与 AI 核心

放置工业控制服务器，使其位于交换机 Wi-Fi 范围或相邻光纤网络中。由服务器所有者、同队成员或管理员打开界面，在 AI 核心槽安装工业 AI 核心，再到“机器控制”页显式启用服务器控制。该槽一次只接受一个工业 AI 核心；没有核心或控制未启用时，服务器不执行自动控制。

服务器可按物品注册 ID 和目标数量请求生产规划。规划器使用 ProcessGraph 给出原料估算、所需机器和工序批次；方案会标注当前网络已识别或未识别的设备，后者不能证明世界里没有设备。已知新配方能量会累加，原生机器耗能和 Create 应力依实际配置核对；没有盘点全世界库存、玩家背包或仓库。服务器分为“状态”“生产规划”“机器控制”三页；在“生产规划”页输入目标 ID 和数量，状态及方案列表可用鼠标滚轮浏览，长行悬停查看。服务器不要求配置 IP、网关、端口、DNS、密码、信道或硬件参数。

自动控制只作用于适配器已识别且实现受控接口的机器，并按机器报告的缺输入、输出已满、缺电、低功率、过载、离线、禁用或错误状态尝试暂停/恢复。状态读取或控制 API 未实现的第三方机器不会因此变成可控机器；不要把网络设备理解为通用遥控器。

## 玩家与实现边界

- 本指南中配方材料数量唯一来源是 ProcessGraph。配方 JSON、JEI、生产规划器和 AI/服务器说明都应读取这份路线，不复制独立配方表。
- 机器槽位仅接受服务端当前登记配方要求的输入；界面说明不能放宽服务器准入。
- 工业网络是数据层；IC2 EU 和 Create 转速仍各自独立。
- 本地 JAR 静态检查、资源文件存在或源码实现不能代替构建成功、模组加载和玩家实机验收。构建及安装状态由主智能体在交付记录中确认。


旧 PCL 安装记录对应先前包体，不能作为新工业阶段已安装或实机验收的证据。

## 终端机存取

终端机的设计与阶段状态见[设计与操作指南](terminal-design-and-guide.md)。终端机具有 144 格容量，界面每页显示 12 列×3 行，共 4 页，容量等价于 12×12 格。终端机不加工物品，只与直接相邻的 Forge 物品接口存取；相邻另一台终端机不会被 AI 托管主动搬运直接连接，两台终端机可以通过既有漏斗或管道衔接。物品通过现有物流设备搬运，工业光纤/WiFi传递数据。

终端机和服务器 AI 提案已实现并通过离线构建，安装版本以交付回执为准，实机效果仍需验收。放下即用：上面和四个侧面输入，底面输出。每面可设输入、输出、双向或关闭；每面最多 9 个白名单幽灵物品槽，全部为空才允许所有类型。按物品类型和方向设置 0 至 9216 留存量：纯输入面不以此值设输入目标；输出面用作最低留存；双向面用作拉取目标，也用作最低输出留存。每面每秒 1 至 64 个物品的速率上限只约束 AI 托管主动搬运。漏斗、管道等既有物流设备的被动插入/抽取按其自身速度工作。

## 工业服务器与玩家本机 AI

玩家在打开的助手界面中使用当前玩家本机已有的 `LLMConfig`。API Key 留在本机，不发送给游戏服务器；服务器只向权限检查通过的请求返回获准网络快照。当前快照最多含 8 台终端机、每台 12 种物品的库存摘要，以及 16 台设备状态，不代表全厂库存；其他模组控制保持只读。

从游戏内操作终端机 AI：右键工业控制服务器，选择“AI 助手”，入口自动使用当前玩家本机已保存的模型设置；API Key 留在本机，不上传服务器。服务器仅在权限校验通过后返回网络快照，当前最多包含 8 台终端机、每台 12 种物品库存摘要和 16 台设备状态，不代表全厂库存。普通按 I 打开的助手不会自动扫描工厂，也不会自动获得服务器快照。

先在服务器右侧槽位插入工业 AI 核心，再到“机器控制”页启用控制；再开启目标终端机的“AI 托管”，配置需要使用的相邻接口面及过滤/留存规则。回到服务器 AI 助手提出终端机规则后，点击“审阅终端提案”，检查内容并由玩家确认，再执行。服务器只应用尚未过期且通过权限、当前网络、终端设置版本与终端机/服务器方块实体身份复查的一次性提案；即使终端机或服务器在原位置拆除后重放，旧提案也会失效。提案有效期为 90 秒（1800 个游戏 tick）。执行结果会显示在游戏聊天中。

AI 托管主动搬运在游戏服务器本地运行，不依赖模型 API；需处于有权限的同一网络、服务器装有 AI 核心、控制已启用且终端机 AI 托管已开启。服务器返回的数据只含经授权快照；其他模组控制保持只读。源码已实现并通过离线构建；实际安装版本以交付回执为准，实机仍待验收。

## 终端机多人使用

交换机、网络适配器、服务器和终端机由放置者 UUID 所有。允许同 Owner、当前 scoreboard 队伍成员或管理员访问；网络同名不授予权限。管理员可建立队伍并管理成员，例如 `/team add 工厂`，随后用 `/team join 工厂 玩家` 让玩家加入（需有相应命令权限）。同队成员可按权限配置终端机或参与控制；离队后队伍权限撤销。其他玩家不能打开他人终端机菜单、查看库存或取物。每次菜单操作、库存访问、快照和提案应用均须服务端校验。这些权限在服务端校验，终端机直接拆除也需要管理权限；公开物品接口供现有物流使用，其实体设施按多人服务器领地规则保护。源码通过离线构建，实机仍待验收。

## 终端机配方与可选 ProjectE

设计配方为 3×3 无序配方，九种材料各一份：`minecraft:chest`、`ic2newera:pcb`、`ic2newera:integrated_circuit`、`ic2newera:cpu`、`ic2newera:gpu`、`ic2newera:industrial_ssd`、`ic2newera:industrial_fiber`、`create:brass_casing`、`projecte:dark_matter`。九种原料 ID 已与当前 ProcessGraph 声明匹配；暗物质 ID 已按当前安装的 ProjectE 原生配方核实。电子材料复用现有真实合成物品；终端机不引入额外一批电子物品。

ProjectE 可选。未安装时不加载暗物质配方和相关批准路线，也没有不含暗物质的替代配方。服务器继续需要 CPU/RAM/工业固态硬盘，AI 核心继续需要 GPU。终端机已通过离线构建，实际安装版本以交付回执为准，实机仍待验收。


## 服务器与助手界面操作

服务器右侧 AI 核心槽独立显示，悬停空槽或已放核心时只显示一份中文槽位说明。服务器和助手使用 Minecraft 的 GUI 坐标；普通 320×240 及更大的 GUI 中按钮、背包和聊天输入区完整显示。AI 助手不暂停单人世界，服务器查询可继续处理。聊天页的长状态和资料发送说明可悬停查看完整内容，切换窗口大小保留草稿及正在进行的请求；关闭助手取消当前请求。

终端机物品仅命名为“终端机”，不附加新纪元自定义物品描述。仓储和过滤规则的操作说明保留在机器界面及本指南。
