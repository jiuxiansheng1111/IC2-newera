# r74 游戏内助手与机器人共用模型

## 玩家设置

在单人或多人游戏中按默认键 I，打开「模型设置」。选择服务、确认 API 地址和授权方式，然后读取当前服务的模型列表。选好默认模型后点击「保存设置」。也可以手动输入服务商提供的模型 ID。助手问答、机器人与手机聊天、智能点歌、歌曲感想与回忆、建筑蓝图共用同一连接。每项功能可以跟随默认，也可以单选同一服务中的另一款模型。图片蓝图需要模型具备视觉能力。

| 服务 | 默认地址 | 模型来源 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1/responses` | API 密钥的模型列表，或通过本机 QQ Cat Robot 已登录的 ChatGPT 获取当前账户的模型列表 |
| Claude | `https://api.anthropic.com/v1` | Anthropic 账户的模型列表，使用原生 Messages 接口 |
| DeepSeek | `https://api.deepseek.com` | DeepSeek 账户的模型列表 |
| Ollama | `http://localhost:11434` | 这台机器的 Ollama 实际提供的模型 |
| 自定义 | 玩家填写 | 兼容 Responses 或 Chat Completions 的服务 |

切换服务后可编辑地址。来自原服务的密钥只用于原服务的来源地址。Ollama 模型列表来自本机服务，并通过原生聊天接口推理。[Ollama 模型目录](https://docs.ollama.com/api/tags) [Ollama 聊天接口](https://docs.ollama.com/api/chat)

Claude 与 DeepSeek 使用各自的模型目录，账户需拥有对应模型的访问权限。[Claude 模型目录](https://platform.claude.com/docs/en/api/models/list) [DeepSeek 模型目录](https://api-docs.deepseek.com/api/list-models/)

已经使用 QQ Cat Robot 的玩家在自己的实例配置目录放置 `ic2newera-subscription-runtime.json`。这个文件仅含本机绝对路径。可以在退出游戏后运行下面的命令填入设置。将三个参数换成自己的实例、项目和解释器路径。

```text
python scripts/standalone-r74/configure_assistant.py --config-dir "<游戏实例>/config" --qq-project "<QQ Cat Robot 工程>" --python "<QQ Cat Robot 工程>/.venv/Scripts/python.exe" --model "<账号可用的模型 ID>"
```

游戏通过 QQ 项目的公开 ChatGPTSubscription 接口调用所选模型，沿用该项目自己的登录。运行路径和认证信息都在各自电脑上。朋友使用自己的账号或服务商密钥。公开登录接口的模型、图片和推理说明见 [OpenAI 的模型与推理文档](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)。

## 多人游戏

客户端和专服均更新到 r74，媒体协议为 10。启用个人模型的玩家发起机器人或音乐对话时，服务器整理此次请求已获权限的上下文，本机调用该功能选定的模型后把文字送回服务器。游戏服务器继续校验实际动作并按玩家及机器人保存音乐记忆。客户端仅接受自己发起、仍在有效期内的请求。玩家关闭个人模型后，机器人可以使用服主已经启用的公共模型。

直接查网易云公开曲目、播放音频和查看短评使用网易云接口。语音由原有语音服务合成。

## 构建与交付

2026-11-16 使用 Minecraft 1.20.1、Forge 47.4.28 和 Java 17 构建。Windows/PCL 包有 46 个模组，本地专服包有 35 个。专服的全部模组与客户端对应文件摘要一致。r74 替换新纪元 JAR，客户端图形资源仍在客户端包。完整文件与校验值在 `dist/IC2-New-Era-r74/`。

玩家已有 r73 时，将新纪元 JAR 同名替换到自己的 `mods` 目录即可。服主正常停服后在专服 `mods` 做同一替换。全新安装可使用对应的 Windows 或服务端包。

## 验收记录

- 在专用单人验收世界通过助手的发送按钮，用同一 Responses 地址分别请求两个模型。`gpt-6-luna` 回答了 5 + 7，`gpt-6.1-sol` 回答了 6 × 8。切换后恢复了这台电脑原定的 `gpt-6-luna`。
- 最终交付 JAR 已在独立验收世界打开通用设置，首次进入即显示实际 API 地址。从「默认与功能模型」读取到 8 个 ChatGPT 型号。将助手问答单独选为 `gpt-5.6-luna`，保留默认型号 `gpt-6-luna`，在游戏中问 9 × 9 得到 81。再次点击「跟随默认」并保存后，各项恢复共用默认型号。
- 通过蓝图推理入口调用 `gpt-6.1-sol` 得到了 2×2×2 的石块蓝图。网易云返回同曲三条公开评论，通过歌曲对话和同一模型连接生成了感想。
- 本机 Ollama 0.33.0 的四条旧索引缺少权重文件。补装官方 `qwen2.5:0.5b` 后，游戏内取得 5 个模型 ID，游戏使用的 Java 推理入口答复 5 + 7 为 12。它的安装大小约 398 MB，核验后已从运行内存卸载。该模型只存在于玩家电脑。[Ollama 官方 Qwen2.5](https://ollama.com/library/qwen2.5:0.5b)
- Claude 和 DeepSeek 的官方模型目录在未提供账号密钥时均返回 HTTP 401。本机用临时接口验证了模型目录和认证头、Claude 原生文字与 PNG 图片请求、DeepSeek 流式中文回复的解析。真实账号的云端推理有待使用者填入相应密钥后验证。
- 本轮验收限于单人世界和模型接口。在线多人服未部署。语音服务在项目盘可用空间低于其 10 GB 阈值时暂停了此次朗读，游戏里的完整文字回复可见。
