## 实现

GPT-6.1 Sol 将游戏请求改为顺序执行的一次性 TTS 和 RVC 工作进程。TTS 构造前直接选定原配置的权重，避免先载入另一角色再切换；TTS 完全退出后才运行本次角色的 RVC。模型不常驻，八角色不会同时载入。仅保存最多8MiB、32条小音频缓存。

游戏专用进程采用 CUDA 半精度、单批次和片段写出，关闭原代码中可选的 G2PW，改用其现有 pypinyin 路径。训练权重不变，多音字读音可能不同。保留模型启动4GiB、运行期间1.5GiB物理内存、85%提交量等保护。模型导入、载入、前端和合成均记录不含凭据的阶段读数。

后续进一步让BERT/HuBERT按最终所需的FP16直接载入CUDA，避免先建立CPU FP32参数再搬运、转半精度。只在游戏worker中使用公开from_pretrained参数；当前已有Accelerate 1.15.0，无须安装依赖，不改第三方文件或全局默认dtype。真实调用已记录 `hf_fp16_direct_cuda`、CUDA半精度和 `g2pw_enabled=false`，并成功完成TTS与后续RVC。

取消和异常收尾改用受控子进程与有界文件日志，等待本次子进程树退出，避免 Windows asyncio 子进程管道在退出时出现关闭错误。仅处理本次创建的工作进程，不关闭用户应用。
