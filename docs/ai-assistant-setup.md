# AI 助手设置

## 支持的接口

游戏内助手支持 OpenAI Chat Completions 兼容接口。设置页用于填写 API 基础地址、模型 ID 和玩家自己的 API Key。模组不会代为创建密钥、猜测模型名或注册服务商账号。

兼容服务通常接收 `POST /chat/completions`，使用 `Authorization: Bearer <API Key>`，请求体包含 `model` 和 `messages`，并在 `choices[0].message.content` 返回文本。客户端会在基础地址后补上 `/chat/completions`；若填写地址已包含该路径，则直接使用。使用不同请求/响应结构或鉴权方式的服务需要额外适配，不能仅靠填写地址接入。

## 游戏内设置步骤

1. 进入游戏后按 `I` 打开“个人工业智能助手”，进入 AI 页并打开“模型接入设置”。
2. 在基础地址栏填写服务提供的 API 根地址，例如 `https://api.example.com/v1`。不要把 API Key 放在 URL 中。
3. 在模型 ID 栏填写服务要求的准确标识。客户端会原样发送该值，不会自动查询或切换模型。
4. 需要认证时填写自己的 API Key；客户端使用 Bearer 方式发送。无需认证的本地兼容服务可留空。
5. 远程地址须使用 HTTPS。HTTP 仅允许 `localhost`、`127.0.0.1` 与 `::1`。客户端不跟随重定向。
6. 开启“AI 服务”，设置请求超时（默认 60 秒），保存并测试，再在对话页发送问题。额度、权限和计费由你选用的服务决定。
7. 按需要开启“联网检索”“本机模组资料”“静态代码资料”。三项默认开启，代码读取依赖本机资料开关；它们不会自动开启 AI 服务。

小窗口和全屏都按 Minecraft 当前 GUI 尺寸重新排版。配置项较多时，在输入区域用鼠标滚轮向下浏览；保存、测试和返回固定在底部。切换全屏或调整窗口大小会保留尚未保存的输入。保存后密钥输入框清空并显示是否已有本机密钥。

### 智谱免费模型预设

设置页的“智谱免费快速问答”按钮会填入 GLM-4-Flash-250414：Base URL 为 `https://open.bigmodel.cn/api/paas/v4`，模型 ID 为 `glm-4-flash-250414`，超时 60 秒，并开启模型请求。已有智谱密钥可以继续使用；没有保存密钥时需在本机输入自己的密钥，再点“保存并测试”。游戏将通过兼容的 `/chat/completions` 路径请求模型。

智谱官方将该型号列为免费模型，支持流式输出与问答。本项目将它作为日常工厂指引预设；不保证服务侧延迟，也不把旧模型的超时直接判定为服务拥堵。模型权益、限流和开放状态以官方模型页和账户当时显示为准。官方指南：[GLM-4-Flash-250414](https://docs.bigmodel.cn/cn/guide/models/free/glm-4-flash-250414)。

客户端使用流式回复，收到正文后逐步显示。若手动选择智谱 GLM-4.5/4.7 等已确认支持关闭思考的型号，会按官方参数关闭思考；其他服务与未知型号不会附加智谱参数。官方说明：[深度思考模式](https://docs.bigmodel.cn/cn/guide/capabilities/thinking)。不会自动切换到收费模型。

API Key 保存在本机客户端 Forge 配置 `config/ic2newera-client.toml` 中，以普通文本存储；不会写入世界存档或多人服务器。保存后输入框会清空，界面只显示是否已保存密钥。留空保存会保留已有密钥；使用清除密钥操作才会删除它。

## 隐私与排错

发送问题时，客户端会把本页对话历史、随包指南相关片段，以及已开启资料功能取得的相关内容发送到配置的 API。本机资料包含模组名与版本、物品/方块名称和注册 ID、客户端已同步的配方；代码资料包含相关模组 JAR 的静态摘要。联网检索会把当前问题和相关模组名称发送至公开搜索服务。不要在问题中包含不希望发送给服务商的信息。

这些资料开关可以分别关闭。普通 I 键聊天不读取工厂运行快照；任何玩家都可从工业控制服务器打开 AI，基于服务器联网设备名单和故障状态进行只读诊断。设备名单也用于 AI 定位设备；异常优先快照最多列 16 台，并附设备总数以及未知、空闲、暂停、故障各自数量。只有拥有当前服务器配置权的玩家可以确认 AI 提案。提案涉及的终端库存规则仍受终端机自身权限约束。摘要不代表全厂库存，玩家背包和存档不读取。界面明确提示快照会发送给当前玩家配置的模型。API Key 只作为认证发往模型接口，不进入检索、资料正文、游戏服务器或其他玩家配置。

发送按钮仅在输入为空或请求尚未完成时停用。配置缺失会显示具体原因并保留问题，不会静默变灰；“取消请求”可结束等待，之后可以重新发送。完整请求受超时上限约束，已经接收到但未完成的正文会保留并标注中断。

- `401` / `403`：检查 Key、模型权限以及服务是否接受 Bearer 鉴权。
- `404`：检查基础地址路径；客户端会补上 `/chat/completions`。
- `429`：查看服务侧额度和速率限制。
- HTTPS/HTTP 验证失败：远程地址须为 HTTPS；HTTP 仅可用于本机回环地址。
- 无法解析响应：该服务可能不是 Chat Completions 兼容格式。
- 超时：先确认服务可用、网络与模型权限；可换用快速问答预设或调整超时。收到流式正文后会边生成边显示，无需等整段回答完成。

## 助手知识

助手可以回答各类模组和一般问题。随包指南重点说明 IC2、Create 与新纪元；其他模组按问题读取本机资料及公开文档。现有两台必要材料处理机、工业服务器和终端机属于当前玩法，化学实验已经退出。

### 单向 EU→Create 电动机

`ic2newera:eu_motor` 源码已实现，增量离线构建成功；最终构建与安装状态见[本阶段交付记录](motor-wifi-access-delivery-2026-10-08.md)，实机验收待完成。它只把 IC2 EU 输入转换为 Create 转轴动力，不反向发电，EU 网和轴系保持独立。界面默认 64 RPM，可选 32/64/128 RPM，输出 1024/2048/4096 SU，固定消耗 10/20/40 EU/t；缓冲 10000 EU。初次启动需要缓冲至少有本档 20 tick 额定电量（200/400/800 EU）。从背面接收 LV 电包，每包最多 32 EU；128 RPM 需要持续 40 EU/t 总供给。供电不足会停机，停机后等待 20 tick 且缓冲达到启动要求才可重启。界面可反转、启停，红石可停机。若轴系已有外部动力源，电动机优先使用外源，本机零发力且零耗电；轴系过载按 Create 规则处理。

当前 ProcessGraph 配方设计是 3×3 无序工作台配方：`create:andesite_alloy` ×4、`ic2:copper_insulated_cable_item` ×2、`ic2:circuit` ×1、`create:andesite_casing` ×1、`create:shaft` ×1。它复用现有材料；CPU、GPU、SSD 不强制用于普通电动机，当前配方也不要求 PCB。源码、构建、安装和实机验收状态须以主智能体最新交付报告为准；在报告确认前，不应称该设备已可用或已实测。

### 自动查阅的资料

- **已安装模组**：读取 Forge 当前加载的模组名称、ID 与版本。可以问“我安装了哪些模组？”；未加载的模组不会冒充本机已有。
- **物品和配方**：按名称或 `modid:item_id` 匹配注册表，以及进入世界后由服务器同步到客户端的配方。自定义机器可能不通过标准配方接口公开数量、流体、概率或工作条件；缺失部分会标为未确认，精确数值仍可在 JEI 核对。
- **代码线索**：在相关模组 JAR 中只读检查最多 4 个类，每类最多 1 MiB。展示类、字段和方法签名、直接调用、条件分支数与相关字符串；类名相似度回退会标为启发式。该功能不会运行模组代码，静态摘要不能证明所有运行行为，也不能凭常量推算能耗公式。
- **公开网页**：尝试模组元数据里的文档链接、Modrinth 项目资料和公开网页搜索，最多读取 4 个来源；检索阶段最多约 12 秒，每个网络读取另有超时和大小限制。部分页面需要登录、重定向或 JavaScript 时可能无法读取，会显示未取得依据。相同查询可使用最多 10 分钟缓存。

聊天页的“资料来源”显示本轮实际发送的本机摘要和网页摘录；可点网页地址打开原文核对。未读取的文档链接不会被当作已查阅的网页证据。回答优先考虑本机版本与配方，再参考文档；资料不足时应说明缺口，不保证任何模组的全部功能都能被自动查到。

可以先问“`create:zinc_ore` 的 ID 和当前配方是什么？”或“查看这个物品的代码实现线索”，再问一个其他模组的问题，核对来源页的结果。联网检索不依赖模型服务提供工具调用，也不需要额外搜索 API Key；模型接口仍使用通用 Chat Completions 协议。

项目中的 IC2/Create 指南、新工业阶段指南和当前电力玩法指南会在构建时打入 JAR，助手按问题选取相关章节。包含四档充电宝、充电台/电池站例外、充电板、EU/p 与 EU/t、变压器方向/红石、过压/核热事故条件、机器人续航和手机操作。还会在开启本机模组读取时，从已安装 IC2 的公开游戏手册资源检索具体物品用途，来源面板显示手册版本与条目。1.19 优先用这一版手册，不用旧在线教程覆盖当前规则。没有世界配置就不能断言本服会不会爆炸。

机器人聊天也使用这套随包知识和已安装手册；专服的批准配方来自服务端 ProcessGraph，普通助手来自服务器同步图。检索只读取公开模组资源，不读取玩家配置或密钥；不会改 Provider、Base URL、Model 或 Key。知识索引有大小和返回条数上限，不能保证未收录的所有模组细节都准确。资料更新后需要重新构建并重启游戏；真实模型答题效果与游戏玩法仍需玩家验收。

2026-10-18 后续：配置好独立语音环境的主机，游戏加载时会自动启动 `tools/robot_voice` 下的轻量协调器；已存在同协议服务则复用，其他服务占端口时保留原服务。新启动进程绑定游戏 PID，退出游戏后取消自己的语音任务并回收。远程玩家不需要这套模型环境。普通 AI 对话页有“朗读：开/关”“朗读上一条”“暂停/继续朗读”“停止朗读”，机器人页面也有语音控制。成功的完整回复会自动分段排队，关掉对话页仍可继续；音量为主音量×语音音量。模型阶段开始前需1GiB空闲物理内存，不足时等待；严格单条生成，最多16条等待，每条从入队起最多10分钟。运行极低余量硬线0.25GiB，85%提交量和磁盘保护保留；1GiB是开始门槛，并非模型内存占用上限。游戏正常退出会删除自己的音频缓存，不删模型。原模型设置无需改动。

手机音乐提供“网易云搜索”和“智能点歌”：前者直接搜歌，不调用模型，也不需要JSON文件；后者使用既有LLM理解自然语言。网易云歌单页面可填写/粘贴公开链接或数字ID，确认后才替换自己的歌单。公开可完整播放的歌曲才可取得音源；不会绕过会员、付费或下架限制。

## 服务器 AI 自动关联与终端调控

### 工业服务器权限与 WiFi 增幅器

任何玩家都可查看服务器状态并打开 AI 做只读诊断。GUI 旁的三档开关决定谁可修改服务器运行参数和控制设备；规划后端及 AI 规划仍保留，但服务器 GUI 不显示规划页或材料流程：

| 模式 | 可修改运行设置、控制设备及确认 AI 提案 |
| --- | --- |
| 0：所有人查看（默认） | root 房主与已授权名单可配置；其他人只读 |
| 1：所有人配置 | 所有人可改运行参数、控制设备和确认提案，但不能切换权限模式或授权他人 |
| 2：仅房主配置 | 只有 root 房主可配置，delegates（授权名单）暂不生效 |

只有 root 房主可切换模式。`grant`、`revoke`、`controller_status` 可由 root 或服务器控制台使用；授权名单只在模式 0 授权服务器配置，获授权者不能再授权他人。模式 0/2 下普通 OP、服务器方块放置者或同队身份不会自动取得配置权。

单人及局域网世界的 root 是 Minecraft 识别的单人世界所有者。专用服务器由控制台或具有权限等级 4 的 RCON 执行 `/ic2newera bind_controller <player>`，按在线玩家 GameProfile 解析并持久保存唯一服主 UUID。未绑定时默认为模式 0，所有玩家只读且无人可切换模式；普通 OP 不能绑定 root。服务器设备列表与 AI 只读诊断源码已实现；构建、安装和验收状态以[阶段交付记录](server-device-list-delivery-2026-10-08.md)为准。

交换机默认 WiFi 覆盖为半径 16 格的球形范围。单个升级槽可安装一个 `ic2newera:wifi_amplifier`，将水平数据覆盖扩到 40×40 格（`dx,dz` 各为 -20 至 19），上下仍各为 16 格。增幅器不可串联或叠加，不是独立方块，不扩展物品物流，也不传 EU 或转速；光纤优先。无线连接只传工业网络数据。服务器 GUI 仅有概览与联网设备两页，显示设备总数、运行数、异常数及每页 3 台设备的编号、名称、连接方式和状态；设备名单不显示坐标。所有玩家均可打开服务器 AI 只读诊断，快照与同一联网设备名单一致，异常优先最多 16 台并附总数及未知、空闲、暂停、故障分类。当前实现状态见服务器设备列表交付记录。

任何玩家右键工业控制服务器都可点击“AI 助手”进行只读诊断；模型读取与服务器一致的联网设备名单和故障状态。所有人配置模式下可由所有玩家确认提案；默认模式下由 root/授权名单确认；仅房主模式下只由 root 确认。读取服务器状态不因此获得他人终端库存，提案确认仍复查终端自身权限。玩家使用自己本机已有的模型配置；普通聊天仍在玩家本机运行。已保存的 Provider/Base URL/Model/Key 继续使用；没有配置或关闭 AI 时仍由玩家在“模型设置”中开启，不自动调用接口。不设置 IP 或网络密码。

服务器插入工业 AI 核心、启用控制，终端机开启 AI 托管后，本地控制器按终端已保存面规则进行相邻物料搬运，无模型 API 时也可运行。生成和执行 AI 控制提案遵循工业服务器当前模式：模式 0 为 root/授权名单，模式 1 为所有玩家，模式 2 仅 root。模型只生成待确认的终端面规则，玩家点击“审阅终端提案”检查完整方向、白名单、留存、速率和托管开关，然后确认。提案单次使用，1800 游戏 tick（正常 20 TPS 为 90 秒）后失效；断网、卸载、拆除重放或设置版本变化也会拒绝。工业服务器模式不会公开或解锁其他玩家的终端库存；终端自身库存和规则仍按终端 Owner UUID、当前队伍或管理员权限校验。其他模组尚未接入的控制能力继续只读，不宣称可遥控所有机器。

完整 Markdown 仍随 JAR 打包；每次发送前按问题选择相关章节，优先匹配章节标题。本轮随包片段最多 2500 字符、本机资料约 5000 字符、网页摘录约 3500 字符，避免把全部模组代码或指南塞入请求；没有选中的信息不能被当作本轮已提供的依据。

网络发现和状态说明：计数为已加载、已发现的联网设备，发现范围上限为32台交换机、256段光纤、128台网卡，每次索引最多256个候选，终端计数最多32台。AI机器样本最多16台且异常优先；超过采样范围时不能声称排查了全厂。运行数读取公开活动/转速或受控接口；第三方设备未提供活动状态时显示未知，普通待机与手动暂停不计为故障。原生IC2/Create未提供的缺料、输出堵塞原因不能推测。只读查询不会触发机器启停。
