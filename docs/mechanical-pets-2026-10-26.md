# 1.20.1 机械猫狗与 Create 扩展

## 本轮依据与交付边界

用户本轮明确要求 Forge 1.20.1，加入机械动力：老吴学和 Create: Biotech；新增有独立互动面板的机械猫、机械狗。用户先否决简陋金属盒草稿，随后明确指出代理误做的圆球动物猎奇，并重申必须是 vanilla Minecraft 方块动物。最新要求为仅 cuboid、整数网格/坐标/尺寸/pivot、方正敦实低重心。金属盒草稿与 `organic` 圆面路线均已作废，不能作为最终资源。

建模沿用项目已经采用的教程、目标版本实际资源校准、可编辑源模型、贴图、生成脚本、索引和真实模型预览的要求。本次读取 1.20.1 的 CatModel/OcelotModel、WolfModel 和对应实际客户端资源，记录来源与指纹。用户给定 [Blockbench MCP 原项目](https://github.com/jasonjgardner/blockbench-mcp-plugin) 与 [建模标准教程](https://xingduansuzhao.com/model)，明确仅用长方体和阶梯结构、有限像素色板，不用球体、圆柱、曲面、斜切或高分辨率噪点。16单位模型网格与贴图像素尺寸是两个概念；本轮 cuboid 与 pivot 均为整数、静态旋转为 0，骨骼动画可平滑插值。不修改依赖模组原有模型。预览直接渲染 `.bbmodel`，不能用概念图替代运行资产。

工程仍在 `build-isolated/migration-1201/newera`，旧 1.19.2 工程和存档不迁移。

### 本轮最新外观与动作修订

用户已认可方块狗外形，并要求仅将躯干稍微加长：躯干长度由8单位改为10单位，前腿前移1单位，头脸/毛色保留。四腿均为独立骨骼，正面左右留2单位空隙，侧面前后腿分开。

猫以用户给定两张橘金猫图片作外形/毛色参考，图像本身不装入资源、不公开上传。用户随后否决夸张眼框与大拱额纹，要求恢复前版简单可爱的像素眼、小鼻子；橘金与奶油色分区保留。用户最初选无火焰后明确改为加火焰，最新要求是保留尾尖火焰，并将两侧小翼扩大为洁白天使羽翼：侧面覆盖躯干70%以上，可以超出躯干左右上下。羽翼仍用整数正厚度cuboid和阶梯式羽片，不能改成曲面。最终羽翼与躯干侧投影相交面积为每侧20/24格（83.33%），超过70%要求，源模型及实际渲染已经导出；最终猫稿仍未获用户审美验收。

动作最新要求为流畅轻柔、有细微生物晃动。运行时使用每只实体独立的6刻姿态缓动、静止躯干微摆、头尾低幅摆动、羽翼对称轻扇。躯干待机晃动不传入脚的骨骼，避免站立滑脚；基础几何及pivot保持整数，动画连续插值。尾焰仅自身局部发亮、柔和变化，不改变其他身体亮度。

## 已实现源码

- 实体与摆放物品：机械猫、机械狗；摆放后归玩家所有。右键面板有跟随/等待、和平相处、抚摸、跳一跳、点头、摇头、跳舞；卖萌页有歪头、抬爪、伸懒腰、打滚、鞠躬、打哈欠。
- 面对面且未设和平的猫狗会轮流扑近、挥爪、击退和后退；不调用伤害接口。打开面板、玩家互动、等待或任一方切换和平会中止。移动前检查地面、碰撞和液体，不将世界环境伤害宣称为免疫。
- 跳跃使用服务端真实垂直运动；摇头点头、嘴部打哈欠、抬爪和舞蹈是客户端骨骼动作。
- 机械猫被真实铁砧或 Create 碾压机伤害触发压扁。主人持铲取回为携带个体数据的机械猫饼。真实旋转的 Create 鼓风机气流持续吹到猫饼后复原；没有面板一键复原。保留 UUID、主人、名字、跟随/和平状态和饥饿值，防止在已加载世界中重复复活同一 UUID。
- 机械宠物饥饿为 20 点，仅实体加载时每 2 分钟减少 1 点，满值约 40 分钟耗尽；0 点时每 10 秒扣 1 点生命，可饿死。猫饼状态暂停消耗。没有额外体热系统。
- 机械猫吃鱼；机械狗吃肉或 `laowu:cat_pancake` 普通猫饼。主人可用普通猫饼为已驯服的原版狼回血。机械猫饼永远不是食物，满饥饿或满血不消耗食物。
- 狗的“大狗到底叫不叫”按钮播放用户给定完整音频并伴随舞蹈，再点可停止。音频长 622.714 秒，转为本地单声道流式 OGG；按实体 UUID 隔离播放/停止，死亡、卸载、离开世界或再次点击时停止。仍在实体跟踪范围内但超出可听距离时按引擎衰减静音；后加入跟踪的客户端按服务端播放进度进入，避免整段重播。此音频没有向云端上传。
- 内置 AI 增加宠物专用知识，合成路线进入现有唯一 ProcessGraph，ProjectE 排除宠物与身份猫饼，猫饼不加入创造栏。
