# 模型、贴图与设备槽位规范

本文规范当前模型资源与设备 GUI，配合《集成当前规格》使用。两台加工机和工业网络设备已经进入本阶段构建及安装包；运行效果仍待玩家验收。服务器目前只有一个可安装 AI 核心的槽位，CPU/RAM/SSD 属于合成材料，不能描述为可插拔硬件。

## 资源位置与命名

运行时资源位于 `src/main/resources/assets/ic2newera/`。命名采用注册 ID 的小写蛇形写法，模型和贴图的材料名、阶段名必须与物品或方块 ID 一致。

| 注册 ID | 模型 | 贴图 |
| --- | --- | --- |
| `nickel_ore`、`chromium_ore`、`titanium_ore`、`tungsten_ore` | `models/block/<id>.json`；物品模型 `models/item/<id>.json` | `textures/block/<id>.png` |
| `nickel_dust`、`chromium_dust`、`titanium_dust`、`tungsten_dust` | `models/item/<id>.json` | `textures/item/<id>.png` |
| `impure_nickel_dust`、`impure_chromium_dust`、`impure_titanium_dust`、`impure_tungsten_dust` | `models/item/<id>.json` | `textures/item/<id>.png` |
| `nickel_ingot`、`chromium_ingot`、`titanium_ingot`、`tungsten_ingot` | `models/item/<id>.json` | `textures/item/<id>.png` |

方块贴图使用 `textures/block/<block_id>.png`，普通物品使用 `textures/item/<item_id>.png`。文件名、模型 `layer0`/方块 `all` 引用和注册 ID 不得各自另取简称。小材料只做物品图标，不为粉末或锭新增世界方块。

## 像素尺寸、轮廓与模型

- 标准方块模型以 16×16×16 模型单位为上限，`from` / `to` 必须落在 0 至 16；不得因装饰把方块几何伸出格子。
- 矿石是静态整块纹理，模型使用 `minecraft:block/cube_all`，六面引用同一张 `all` 贴图。矿脉只画在方块像素内。
- 有朝向的设备模型须明确区分 `north`、`south`、`east`、`west`、`up`、`down` 面，并让 blockstate 的朝向变换和显示的正面一致。不要把某一张正面纹理无意贴到全部方向，也不要让 GUI/模型朝向和方块朝向各说各话。
- 粉末、锭和材料图标使用 16×16 PNG、透明背景及 `minecraft:item/generated`。锭画成可读的金属条轮廓，粉末画成粒状堆；不要使用 `minecraft:item/handheld`，避免小材料在手持视图变成大模型。
- 轮廓可以借鉴原版与 IC2 的像素层次，但必须由项目自行绘制：用一至两级暗边、主体色块和少量高光建立形体；禁止复制第三方 PNG 或逐像素描摹他人贴图。
- PNG 使用整数像素绘制，关闭抗锯齿；避免模糊渐变、半透明边缘和过密噪点。图标缩到原始 16×16 查看时仍需辨认材质与阶段。

## 四种矿物的辨识规则

本批核心资源由 `art/sources/generate-core-mineral-assets.py` 生成，脚本只使用项目内定义的颜色和像素形状，可重复生成下列 16×16 资源。

| 材料 | 主色调 | 阶段辨识 |
| --- | --- | --- |
| 镍 | 灰绿、浅银 | 矿石为灰岩中的鼠尾草绿矿脉；净粉明亮、颗粒细；含杂质粉增加深色碎粒；锭用灰绿金属条与浅色高光。 |
| 铬 | 矿脉暗红；粉与锭亮银灰 | 矿石呈棕红色矿脉；精炼铬改用银灰金属高光，避免把铬金属画成铜。含杂质粉增加灰褐碎粒。 |
| 钛 | 蓝青、冷银 | 冷青色矿脉及粉尘，锭呈蓝灰色；避免与镍的灰绿色混淆。 |
| 钨 | 深紫灰、淡金高光 | 矿脉和粉末采用深紫灰，锭用紫灰金属与少量淡金高光，和钛的蓝青色明显分开。 |

每种材料的矿石矿脉颜色应在灰石背景上有清楚明度差。普通粉保持干净、较亮；含杂质粉在相同材料色系上增加数颗明显的暗色碎石，不得仅改名称或做轻微色偏。锭需保留各自色系，不得四种都成为同一银色图标。

## GUI 槽位与 `mayPlace` 一致性

槽位的中文悬停说明必须描述服务器端实际准入条件。GUI 客户端不能单独放宽或缩小允许物品范围；服务端 `Slot.mayPlace`、配方匹配和提示文案应共用同一条接受规则。配方或 Tag 变化后，槽位提示也要同步更新。

通用文案模板：

```text
输入槽：仅接受本设备当前配方所需的输入物品。
输出槽：用于取出本设备产物；不能放入物品。
副产物槽：仅接受服务端规则允许的副产物/容器（若实际实现）。
```

只有当 `mayPlace` 确实按对应配方输入或物品 Tag 校验时，才可把“仅接受配方输入”写进提示；如果实现只检查自定义 Tag，文案必须写明该 Tag 所代表的物品范围。输出槽若服务端允许回填，也不得显示为“不能放入”。不能仅凭槽位位置或客户端按钮推测服务端规则。

### 当前设备说明

两台设备已在当前源码注册并提供菜单。实际提示使用 `ProcessorSlotRoles.acceptedInputs` 与服务端准入相同的配方候选；原生 IC2 槽位使用其公开的 InventoryHandler 类型登记。下列文案作为简明用途说明，具体候选原料按当前同步配方显示：

| 设备 | 计划用途 | 输入槽悬停文案模板 | 输出槽悬停文案模板 |
| --- | --- | --- | --- |
| Non-Metal Processor（非金属处理机） | Quartz Dust → Silicon；Silicon → High Purity Silicon | `非金属原料输入槽：放入当前配方要求的石英粉或硅。实际可放物品以服务端配方校验为准。` | `非金属产物槽：取出当前配方的硅或高纯硅。` |
| Electronic Fabricator（电子材料加工机） | PCB、Integrated Circuit、CPU、RAM、GPU、Industrial SSD | `电子元件输入槽：放入当前配方所需的电路、硅材料或 Create/IC2 元件。` | `电子元件产物槽：取出当前配方制作的元件。` |

落地时必须让文案中的输入类别和 `mayPlace` / 配方匹配范围吻合；若实际配方只允许其中一种材料，应把宽泛模板改成该材料的准确名称。不要为了让 GUI 看起来完整而新增规格未要求的加工机器或槽位。

### 服务器硬件与 AI 核心槽

当前服务器合成强制使用 CPU、RAM、Industrial SSD，没有分别安装这三种材料的槽位。唯一模块槽一次只接受一个工业 AI 核心，放入、取出和远程操作都检查所有者/当前队伍/管理员权限。核心槽中文提示说明用途；没有核心时自动控制不可启用。基础硬件采用只读说明：

```text
服务器硬件（只读）
CPU：由服务器合成配方提供
RAM：由服务器合成配方提供
Industrial SSD：由服务器合成配方提供
```

若未来规格明确增加可插拔硬件槽，每个槽的中文提示必须和服务器侧 `mayPlace` 使用同一分类：

```text
CPU 槽：仅接受服务端规则认可的 CPU 模块。
RAM 槽：仅接受服务端规则认可的 RAM 模块。
Industrial SSD 槽：仅接受服务端规则认可的工业 SSD。
```

这些提示只在相应服务端校验与取出/替换规则落地后使用；若服务器目前只通过合成配方消耗硬件，就保留只读显示，不伪造物品槽。

## 静态资源检查

本阶段最终包静态核对：63个物品模型、11个blockstate及63条模型索引完整（按当前包实际核对；旧文档blockstate计数有误，旧包实际10个，本阶段只新增terminal）；自有模型几何位于 0–16，所有本模组模型的父级/贴图引用存在。新增小材料使用 16×16 图标，两台处理机以及适配器、交换机、光纤、服务器采用不同造型。父级显示变换沿用原版，手持视觉仍需游戏验收。

生成或修改资源后，至少静态核对：

1. 每个 PNG 可解码，材质图标为 16×16、带透明通道；矿石贴图为 16×16 不透明方块纹理。
2. 四种矿石均有 `models/block/<material>_ore.json`，父模型是 `minecraft:block/cube_all`，`all` 指向本模组对应 block PNG。
3. 矿石物品模型继承本模组 block 模型；十二个粉/锭模型继承 `minecraft:item/generated`，`layer0` 与其纹理同 ID。
4. JSON 可解析；路径大小写、物品 ID、模型引用和贴图文件完整对应。
5. 普通粉与含杂质粉可从 16×16 原图上分辨；四种金属在矿石、粉末、锭三阶段维持不同色系。

本规范的静态核对不替代游戏内的资源重载或模型视觉验收。新增注册、blockstate、语言、配方与实际机器槽位由其负责的实现任务完成，并按上述命名及准入规则接入。
