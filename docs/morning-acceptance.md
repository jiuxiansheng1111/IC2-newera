# 2026-10-08 服务器与 AI 助手界面修复验收

本节为玩家实机观察步骤。源码布局及 JAR 静态检查不代表已经通过实机或模型 API 验收。

1. 在 Minecraft 窗口和全屏之间切换，分别使用自动及可用的 GUI 比例。320×240 及更大的 GUI 中，服务器的标题、AI 助手按钮、三页按钮、核心槽及下方背包应完整显示且不相互重叠。
2. 右键服务器：依次切换“状态”“生产规划”“机器控制”。状态和方案列表可滚轮查看，长行悬停显示完整内容；规划 ID、数量及机器坐标在换页、调整窗口后保留。
3. 悬停右侧 AI 核心空槽，再放入核心并悬停；预期均只有一份换行的中文说明，不与物品的原描述重叠。其他物品仍无法放入。到“机器控制”页确认无核心不能启用、有核心可以按权限启用。
4. 点击服务器“AI 助手”。单人世界应继续运行，发送问题可取得授权快照后进入模型请求，不能因聊天页暂停世界而出现“工厂查询超时或连接中断”。服务商错误和真实网络超时仍需按提示排查。
5. 普通 I 助手的 AI 页按钮显示“AI 助手”。聊天顶部按钮、提案按钮、聊天内容、状态提示和底部输入/发送分别占用独立区域。长状态悬停能看全，不挤到输入框；回复中调整窗口保留草稿与请求。主动关闭/取消后停止当前请求。
6. 打开创造栏或普通背包悬停终端物品：中文名称恰好为“终端机”，不再显示新纪元附加的三行用途/配方描述。第三方模组名标签或原版高级工具提示由相应设置控制。
7. 服务器拆除/离线或退出世界后，返回按钮不得恢复已经失效的旧容器界面。实际请求及提案效果由当前玩家模型和服务端权限决定。

# 当前阶段：四矿、电子材料与工业数据网络验收

本节对应 2026-10-07 已安装的工业阶段包，后面的旧步骤仅作为历史。开发没有启动游戏或运行测试，请由玩家记录观察结果。

1. 从 PCL2 的 Forge 1.19.2/43.5.0 实例启动，进入创造世界；若显示数据包错误，保留 latest.log，不使用安全模式或改存档。
2. JEI 搜索镍/铬/钛/钨：四种基础矿石和各自含杂质粉/净粉/锭名称中文齐全。矿物只生成在新探索区块；不必删除旧世界，验收时也可新建世界。
3. 一矿经 IC2 粉碎机或 Create 粉碎轮应产两份含杂质粉。让 Create 鼓风机的气流穿过水后清洗粉末；杂质粉应不能直接熔炼。原矿直接烧应只得到一锭。
4. 镍/铬净粉应能普通熔炼；钛/钨净粉只能在批准的 IC2 电力高炉或感应高炉加工，普通炉不能加工高级净粉。查看 JEI 是否还有未经批准的捷径。
5. 将下界石英加工成石英粉，打开非金属处理机。给侧/后/顶/底接 IC2 电缆；界面应有 EU，正面不收 EU。悬停空槽/有物槽应显示中文用途及允许原料；错误原料/向产物槽回填应被拒绝。
6. 打开电子材料加工机，点击进度区打开 JEI。按固定六输入位置放料，检查真实数量、产物、加工时间/EU、缺料/无电/产物满提示；用底部漏斗抽取产物。检查机器在手上和世界里不超大，两台外形明显不同。
7. 查看两种 IC2 高级电路的新配方、六种新合金，以及 CPU/RAM/GPU/SSD 路线；电子加工机本身不得依赖它自己制作的 PCB。
8. 放交换机和贴近机器的适配器：默认无需配置，16 格内自动无线加入；光纤相邻连接时优先有线。IC2/Create 显示公开状态，未知字段不冒充正常运行。检查各网络方块模型有明显区别。
9. 放服务器：合成要 CPU/RAM/SSD。核心配方要 GPU，模块槽只收一个核心，错误物品不能放；无核心不能开启本地控制。检查跨队/非所有者不能改设置、取核心或下发控制。
10. 服务器用 `ic2newera:cpu` 及目标数量请求规划，滚动/悬停完整查看 BOM 与工序；未识别机器提示不等于世界没有机器。请求没有批准产路的原矿/其他目标应明确拒绝，不猜造配方。
11. 给新处理机制造缺料或产物满状态，再启用服务器本地控制，检查是否暂停并在排除问题后恢复。原生 IC2/Create 此阶段只读，AI 不应声称可直接遥控所有机器。
12. 按 I 打开普通助手，查看新增工艺节点；拖动暖色科技树，在窗口/全屏和 GUI 比例间切换。向 AI 询问钛粉加工/CPU 用途时，应引用批准路线，不能推荐杂质粉直接烧。普通 I 助手不会自动扫描工厂；要查看授权快照和提交终端机规则提案，须右键工业控制服务器打开服务器 AI 助手。
13. 在 IC2 原生机器里悬停公开类型的输入/输出/升级槽，确认说明位置正确；未公开或通用槽类型允许不加附加说明。不要要求猜测内部槽号。

### Macerator 界面说明补丁

安装本次答疑补丁后，问随包 AI：“粉碎机左上角 I、C、S 各是什么？有效格子输入是什么意思？右边四格是什么？”预期答复：`I` 是机器访问控制，`C` 是比较器设置，`S` 是格子过滤器信息/有效格子输入；I 面板的 `D/U/N/S/W/E` 才是方向缩写，其中 `S` 是南；左下两个红叉分别限制每格一个物品、每种物品一组，默认红叉表示关闭；右侧四格是可选升级槽。再依次点 I/C/S 并悬停主要控件：I 面板解释六面访问与导入/导出，C 面板解释红石状态信号，S 面板列出所选槽位允许的物品；确认它没有把菜单字母说成一个“ICS”标签，并检查两个红叉悬停已显示中文。

# 后续阶段：工业终端机、AI 提案与多人权限验收

本节对应[工业终端机设计与操作指南](terminal-design-and-guide.md)。终端机与服务器 AI 提案已接入源码；干净编译起始后的离线构建曾成功一次，之后提案防重放经审阅又有源码更新，最终构建待主智能体再次执行并记录。尚未安装或实机验收。

## 终端机配方与界面

1. 在 JEI 确认终端机为 3×3 无序配方，九种材料各一份：箱子、PCB、集成电路、CPU、GPU、工业固态硬盘、工业光纤、Create 黄铜机壳和 ProjectE 暗物质。核对配方 ID 与当前 ProcessGraph 声明一致；`projecte:dark_matter` 已按当前安装 ProjectE 原生配方核实。确认没有额外无暗物质替代配方。
2. 在安装 ProjectE 的实例中确认配方和依赖暗物质的批准路线可用；在未安装 ProjectE 的实例中确认只跳过相关配方/路线，且模组仍能正常加载。不要把未装 ProjectE 的情况写成终端可合成。
3. 放置终端机，确认单方块外形和 144 格库存；界面每页应为 12 列×3 行，共 4 页，所有页容量等价 12×12，且小窗口（320×240）可正常操作。确认终端机不加工物品，放下后默认无需菜单配置即可存取。

## 相邻物品接口与自动搬运

4. 用可观察库存的原版箱子或测试容器分别连接终端六面，核对上面和四侧默认输入、底面默认输出。确认只对直接相邻且公开 Forge 物品接口的方块工作。
5. 逐面设置输入、输出、双向、关闭，分别验证搬入/搬出方向；确认相邻 IC2/Create 既有运输设备可接接口，网络连接本身不会远程搬运物品。将另一台终端机直接相邻放置，确认 AI 托管主动搬运跳过终端机接口以避免循环；再用漏斗/管道连接两台，确认可通过既有物流衔接。
6. 每面添加 1 个及最多 9 个幽灵白名单物品，确认幽灵槽不占终端库存。白名单非空时仅搬运所列类型；清空后该面接受所有物品。
7. 对一种物品设置保留量 0、中间值和 9216：纯输入面不以保留值作为输入目标，默认 0 仍应正常输入；输出面应至少留下设置数量；双向面将其作为拉取目标且作为最低输出留存。
8. 各面分别设置每秒 1 个和 64 个上限，在 AI 托管主动搬运时按实际服务器 tick 观察，确认上限生效。另用漏斗、管道等既有物流被动插入/抽取，确认它们按原有速度，不受终端机的 AI 托管速率设置限制。空接口、满库存、过滤、留存和关闭面均应停止对应搬运并显示可理解状态。
9. 重启世界后检查库存、方向、白名单、预留值、速率与托管开关是否正确保存；修改或快速连续操作时检查服务端最终值与界面一致。

## AI 提案与权限

10. 确认助手使用打开界面的当前玩家本机 `LLMConfig`。检查游戏服务器请求/日志/配置中不包含玩家 API Key；断开或未配置模型时，终端现有库存与本地搬运仍可工作。
11. 对有权限的网络请求快照，核对最多返回 8 台终端机、每台最多 12 种物品库存摘要及 16 台设备状态；确认这不是全厂库存，未支持机器字段显示未知或只读。无权玩家不得取得快照。
12. 右键服务器打开“AI 助手”，确认它自动使用当前玩家本机已有的模型设置。提案有效 90 秒（1800 个游戏 tick）且单次使用。让助手提出终端机方向、白名单、留存量、主动搬运速率和托管开关变更；点击“审阅终端提案”，确认玩家可检查并确认后再执行，执行结果出现在游戏聊天。服务端应重新校验请求者权限、当前网络、终端机设置版本、规则参数及终端机/服务器方块实体身份。构造过期、重复使用、设置版本变化、越界数值、无权限请求，以及终端机或服务器在原位置拆除后重放的情况，确认服务器拒绝旧提案。
13. 确认提案不包含任意物品传送、直接控制第三方机器或绕开服务端权限的操作。其他模组的未支持控制只读。
14. 按操作顺序插入 AI 核心、启用服务器控制、开启终端机 AI 托管并配置相邻接口面，确认托管主动搬运还需要双方处于有权限的同一网络；缺少任一条件时不搬运。条件满足后，确认搬运在服务端本地执行，即使没有模型 API 也可继续按保存规则运行。

## 多人权限

15. 由玩家 A 放置交换机、适配器、服务器和终端机；确认 A 可用。玩家 B 与 A 同队时，按设计验证其可查看/配置的范围；B 离队后权限应立即撤销。
16. 玩家 C 与 A 不同队时，分别尝试打开终端机菜单、查看库存、取物、读取网络快照、提交/确认提案和更改网络名，均应由服务端拒绝。将交换机改成相同网络名后重试，确认同名不产生授权。
17. 管理员执行 `/team add 工厂` 并使用有权限的 `/team join 工厂 玩家` 流程，确认队伍状态以服务端当前 scoreboard 为准。测试踢出/离队后的即时撤权，以及所有者变更或方块重新放置时 Owner UUID 处理。
18. 尝试绕过界面直接发库存/菜单/提案请求，确认每个服务端入口都独立校验 Owner UUID、当前队伍和管理员权限；权限数据不可用时拒绝敏感操作。

19. 普通按 I 打开的助手不应自动扫描工厂或自动取得网络快照。只有右键工业控制服务器进入 AI 助手，且请求者权限通过后，才能取得受限的服务器快照并提出终端机提案。

## 以下为历史验收步骤

# 当前版本人工验收

此清单用于用户在 PCL2 的目标实例中核对当前安装版本。本文记录的是待验收步骤，不代表已经启动游戏或通过实机验证。

## 内容与界面

1. 确认世界可正常加载，没有数据包或注册错误。
2. 在世界中按 I 打开助手；小窗口与全屏科技树均为米色/铜棕色。按住左键或中键拖动应平移画布，单击节点应打开详情；全屏滚轮缩放，右键取消选择，Home 回到总览。拖动节点时不应误打开详情，松开后继续移动鼠标不应继续拖动。
3. 打开 AI 助手，确认可访问设置和对话界面；未配置服务时不应暗示其已连通模型服务。
4. 在创造栏、JEI 和科技树中核对：四矿、电子中间体、两台必要处理机、工业服务器与终端机均可查；无退役化学实验或重复矿物炉。终端机配方强制原版箱子、CPU/GPU/SSD/PCB等电子中间体与ProjectE暗物质。

## IC2 与 Create 联动

1. 按 [联动指南](ic2-create-integration.md) 分别搭建 IC2 EU 供电与 Create 转速传动，确认各自的原生机器能够工作。
2. 确认矿石来源是 Create 自带的锌矿石；用 JEI 检查粗锌/粉碎粗锌进入 IC2 粉碎机、每份输出 2 份新纪元锌粉，锌粉再熔成 Create 锌锭。
3. 再查 Create 粉碎铁、铜、金、锡、银、铝各进入 IC2 粉碎机，输出同种 IC2 金属粉；铝的两端 ID 分别使用 `aluminum` 和 `aluminium`。
4. 确认没有 EU/转速转换设备或配方。跨模组联动应表现为物品输入和输出。
5. 按 JEI 实际显示核对合金与装备配方；文档中的示例不能替代实例配方。

## 成就中文与助手查阅资料

1. 语言选为简体中文，打开原生成就界面及助手科技树，检查 IC2 核弹击杀凋灵、末地改造、脚手架与采矿激光枪击杀末影龙的标题和说明。末影龙说明不应再写成凋灵；Create 伸缩抓手成就标题应显示“咻——！”。
2. 在 AI 设置滚动查看三个新开关；切换全屏后草稿不丢失，固定底部按钮不重叠。代码开关关闭或本机资料关闭时，不能继续发送代码资料。
3. 问“我安装了哪些模组？”与具体物品 ID 的用法，打开“资料来源”检查安装版本、注册 ID 和同步配方。自定义机器无法读取的数据应写明未确认，不冒充实际配方。
4. 开启代码资料，询问某个注册 ID 的代码实现；来源应区分直接实现类与类名相似度匹配，并注明静态摘要的范围。
5. 开启联网检索，询问另一模组的功能；核对来源中的实际网页摘录和链接。联网失败应显示不可用原因，仍可使用已有本机资料；关闭联网后不应访问搜索服务。
6. 在小窗口、最大化和全屏之间切换，检查聊天、设置、来源页的滚动和按钮；发送、取消与完整超时后仍可再次发送。

上述新增功能尚待玩家实机确认；构建成功不等于服务连通或视觉验收。
