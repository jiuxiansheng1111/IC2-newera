# 工业终端机设计与操作指南

> 状态：源码、最终干净构建和PCL安装均已完成；实机与模型API尚未验收。具体版本/哈希/回执见 terminal-stage-delivery.md。

## 目标与范围

工业终端机是单方块物品库存与局部搬运控制点，具有 144 个槽位。为适配 320×240 等小窗口，界面每页显示 12 列×3 行，共 4 页；容量等价于 12×12 格，不会在单页同时显示全部槽位。终端机本身不加工物品。IC2 电力、Create 转速、物品管线和流体管线仍由各自现有系统负责；工业网络只传状态与控制数据，不能把物料经光纤或 Wi-Fi 远程瞬移。

只与相邻方块公开的 Forge 物品接口交互。相邻 IC2 或 Create 运输设备可照常连接终端机的物品接口；终端机不替代它们的管道、漏斗、传送带或库存，也不直接调用私有槽位实现。

## 默认存取与方向设置

放下终端机即可使用，无需打开菜单配置。默认上面和四个侧面接受相邻接口输入，底面提供输出。每个方向可单独设置为“输入”“输出”“双向”或“关闭”。方向设置控制终端机与该面相邻物品接口之间的存取。

AI 托管主动搬运仅检查与终端机直接相邻且已加载的物品接口，并排除相邻的另一台终端机，避免两台终端机之间形成双向搬运循环。每一面可单独设置主动搬运速率上限，范围为每秒 1 至 64 个物品；按物品数计，不是堆叠数。这个上限只约束 AI 托管的主动搬运。漏斗、管道等现有物流设备对终端机进行的被动插入/抽取仍按各自物流速度工作，不受该上限影响。终端机之间可通过既有管道或漏斗衔接。

## 白名单与库存预留

每个方向最多有 9 个白名单幽灵物品槽。幽灵槽仅记录物品类型，不存入实际物品，也不占用终端机的 144 个库存槽位。白名单非空时，该方向只搬运列出的类型；白名单为空时接受所有类型。

每个方向可按物品类型设定保留数量，范围为 0 至 9216。纯“输入”面不以此值设输入目标，默认值 0 时仍正常输入；“输出”面把它作为终端中该物品的最低留存量；“双向”面既把它作为从相邻接口拉取时的目标数量，也作为向外输出时的最低留存量。默认保留数量为 0。

库存已满、相邻接口拒绝物品、方向关闭、白名单不匹配、输出留存量已达到或托管主动搬运速率额度用尽时，应显示能让玩家理解的状态。服务端搬运判断是最终依据，界面预览和 AI 建议不能放宽这些限制。

## 网络与自动搬运

终端机可以独立存取物品，不要求网络、服务器、AI 核心、模型 API 或菜单配置。漏斗和管道等既有物流设备可被动插入或抽取。接入工业网络后，数据网络只用于状态查看和经授权的控制请求，物品仍须通过相邻 Forge 物品接口搬运。

可选的终端机 AI 托管主动搬运需同时满足：终端机和工业控制服务器处在有权限的同一网络、服务器装有工业 AI 核心、服务器控制已启用、终端机加入服务器托管。满足这些条件时，游戏服务器按已保存且经过校验的终端规则在本地执行搬运，不调用玩家模型 API 也能工作。未满足时，漏斗和管道等既有物流设备仍可按其自身机制插入/抽取；服务器不能因此获得终端机控制权。

交换机的光纤优先和 Wi-Fi 16 格规则沿用现有工业网络设计。物料不会因为终端机、服务器或交换机联网而跨距离移动。跨区域传送仍须由 IC2/Create 等既有物品运输设备完成。

## 工业服务器与本机 AI 助手

预期的 AI 使用方式是在玩家打开的助手界面中，使用当前玩家本机已有的 `LLMConfig`。API Key 留在玩家本机，不上传到游戏服务器。游戏服务器只向已通过 Owner UUID、当前队伍或管理员权限校验的请求返回允许查看的网络快照。

当前网络快照最多包含 8 台终端机、每台最多 12 种物品的库存摘要，以及最多 16 台设备的状态。它不是全厂库存盘点，也不包括玩家背包和未连接仓库。第三方或原生机器只有公开且已接入的状态才会显示；未支持的状态应标为未知或只读，不能编造成已识别、可控。

助手根据授权快照生成结构化的终端机各面规则提案；提案有效 90 秒（1800 个游戏 tick），且只能使用一次。玩家明确确认后，服务器再次核对请求者权限、当前网络、终端机设置版本（settings revision）、终端机与服务器的当前方块实体身份和规则取值，全部通过才应用。过期、重复使用或检查不匹配的提案必须拒绝；终端机或服务器即使在原坐标拆除后重新放置，旧提案也必须失效。提案仅覆盖终端机方向模式、白名单、保留量、每面主动搬运速率和终端机 AI 托管开关，不直接发出任意命令，也不代替玩家确认。其他模组控制保持只读。

普通按 I 打开的助手不会自动扫描工厂。实时授权快照与提案只能通过工业服务器的 AI 助手入口取得；任何返回给本机模型的数据均先经过服务端权限校验。

本地配置的模型不可用时，终端机库存和已配置的本地规则仍可工作；不能把 API 连接失败表述成终端机基础存取失效。工业服务器本身只在已有功能范围内执行服务端权限检查与状态服务，不接收或保存玩家模型 API Key。

## 多人所有权与队伍

交换机、网络适配器、工业服务器和工业终端机由放置者的 UUID 所有。仅同一 Owner 或当前 scoreboard 队伍中的成员可使用对应网络；管理员按服务端管理权限处理。网络同名只用于识别网络，不会授予访问权限。

管理员可用 `/team add 工厂` 建立队伍，再用 `/team join 工厂 玩家` 邀请/加入玩家（具体权限以服务端命令权限为准）。同队成员可以按终端机授权规则查看或配置终端机，以及参与服务器控制提案；离队后队伍权限立即失效。不同所有者且不属于同一当前队伍的玩家不能打开他人终端机菜单、查看其库存或取出物品。UI 隐藏不足以构成安全边界，所有菜单操作、库存访问、网络快照和提案应用都必须在服务端重新校验权限。

若队伍 API、管理员判定或所有权数据不可用，应拒绝敏感操作并显示权限错误，不以相同网络名作为回退授权。

终端机使用 3×3 无序合成配方。下列九项 ID 已与当前 ProcessGraph 声明核对；`projecte:dark_matter` 另已通过当前安装的 ProjectE 原生配方核实：

| 1 | PCB | `ic2newera:pcb` |
| 1 | 集成电路 | `ic2newera:integrated_circuit` |
| 1 | CPU | `ic2newera:cpu` |

ProjectE 是可选模组。只有检测到其物品注册存在时才注册这条终端机配方及依赖暗物质的批准路线；未安装 ProjectE 时跳过该配方/路线，不注册不含暗物质的替代终端机配方。其他电子物品必须复用新纪元已有的真实合成材料，不为终端机额外新增一批同功能电子物品。服务器的 CPU、RAM、工业固态硬盘要求与 AI 核心的 GPU 要求继续沿用现有规则。

## 玩家快速排查

物品没有存取时，依次检查：相邻方块是否公开 Forge 物品接口、接口方块是否加载、方向是否允许当前搬运方向、白名单是否为空或包含该物品、输出留存/双向拉取目标是否满足，以及输入/输出接口是否有空间。每面速率只限制 AI 托管主动搬运；若涉及该模式，再检查网络权限、服务器 AI 核心、控制是否启用、终端机 AI 托管是否开启。相邻的是另一台终端机时，AI 托管主动搬运会跳过该接口；可改用既有漏斗或管道连接两台终端机。

库存或机器状态不可见时，检查玩家是否为设备 Owner、同一当前队伍成员或管理员，以及目标机器是否属于已支持状态读取范围。网络名称相同不代表有权查看。不要通过拆除他人终端机、改名网络或复制方块来绕过服务端权限。
