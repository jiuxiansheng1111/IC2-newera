# r46：机器人协作建造、文件图纸与图片外观规划

2026-10-27。用户要求多个机器人按描述或文件合作施工，三类图纸均接入，外部造型优先，内部由玩家微调。网盘中的“所有模组.zip”需要登录，用户选择先做协作建造；没有下载或检查其中未知模组，不能宣称本实现就是视频或网盘中的同一模组。

## 已实现

- 选择1–8名机器人（包括领队）；服务器锁定同主人、同维度、64格内已加载且可施工的实际成员。共享计划与进度持久保存，施工格由成员认领，防止重复耗材；暂停、继续、取消覆盖整队。成员暂时缺料、没电或通路不通时保留进度。各自从自己的货物槽取料，材料不会在队员间凭空转移。
- 原版结构 `.nbt`、Sponge `.schem` v2/v3、`.litematic`、内嵌贴图的cuboid `.bbmodel` 和紧凑 `.json` 文件导入。只读取建筑方块，不导入实体、库存或命令，也不能上传工业生产程序绕过ProcessGraph。已有受控生产线规划仍由原规划器批准；生产团队完工后只有领队接管生产，协作者待命。
- 工作页“建造与生产线”增加“文件图纸 / 图片”、打开目录、刷新、拖入文件、旋转/缩放布局预览和成员数。预览使用实际施工方块坐标与近似颜色，阶梯/半砖形状和贴图细节以游戏实物为准。
- 自由描述“AI创作”和PNG/JPG参考图片通过玩家已有AI配置生成三维方块方案。图片需要视觉模型；优先外轮廓、比例和配色，曲线用方块阶梯层次及半砖/阶梯近似。单张图不可见部分只是合理推断，不能保证精确还原。AI缺失、超时、不支持图片或JSON非法会明确报错。
- 文字/图片发送至玩家配置的AI服务。图片和API密钥不发给Minecraft服务器，服务器只接收图纸或生成的JSON。先检查实际材料、位置、权限与成员，再由主人点“开始施工”。图片规划、解析或上传不会自动开工。
- 真实生存放置沿用既有机器人逻辑，启动每名成员200 EU、逐块放置消耗真实物品与电量。高处与封闭房间需要可达通路/脚手架，不瞬移、不凭空生成材料、不自动拆除已有方块。取消保留已放建筑。

## 提交图纸

当前游戏版本目录下固定为 `IC2-NewEra-blueprints/inbox`，可用游戏按钮打开。本机独立1.20.1实例已建立该目录，并放入 `example-house.json` 和 `README.md`；桌面有“机器人建造图纸”快捷方式。将文件放进去后刷新，选择人数、解析预览，再开始。

AI生成文件保存到 `IC2-NewEra-blueprints/generated`；要编辑后重新导入，复制到inbox或拖进建造窗口。服务器将接受的原文件按主人UUID归档到received，每人最多64份/128 MiB，不保存API凭据。详细格式与限制见独立工程 [图纸说明](../build-isolated/migration-1201/newera/art/robot-blueprints/README.md)。

单个上传最多8 MiB，NBT解压最多16 MiB，最多16,384构件，范围97×65×97格；序列化计划不超过1,750,000字符，为机器人娃娃2,000,000字符的任务恢复上限留出空间。超过限制须拆分。累计操作/模型采样最多1,000,000；Blockbench最多64张内嵌贴图、总计16,777,216像素。外部贴图路径、网格曲面、未知或无法真实放置的状态会拒绝。部分方块邻接状态由原版自动生成，双半砖和床等当前不支持。
