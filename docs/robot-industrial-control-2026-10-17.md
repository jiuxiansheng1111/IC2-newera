## 制造与开始使用

1. 按科技检索或 JEI 制作通用图纸；图纸合成娃娃后返还。
2. 用已有电子材料加工机制造机器人控制核心、执行器和电池。核心使用 CPU、RAM、GPU、工业 SSD、IC2 高级电路和兰波顿水晶；执行器使用钛合金、碳化钨、Create 精密构件及 IC2 高级材料。详细数量、真实物品 ID 和加工能耗见 [配方记录](robot-industrial-recipes-2026-10-17.md)，唯一工业配方源仍为 ProcessGraph。
3. 核心、执行器、图纸、羊毛、线和对应发色染料合成娃娃。八种娃娃不附带电池。
4. 将机器人电池放进IC2 MFSU 或更高等级储电设备的充电槽或同级充电台（最低三级）充电。电池容量 **4,000,000 EU**，最大传输 **2048 EU/次**，新合成电池为空电。复用 IC2 `IDamagelessElectricItem` 与原生充放电管理器，没有另造能源网络。
5. 放置娃娃，右键机器人，再打开“电池/装备”。电池槽仅收机器人电池；主手可装斧、镐、武器；副手用于携带；防具槽按部位校验。九格货物接收工作掉落。每种槽位都有中文悬停说明。

## 电量、寿命与物品保存

| 动作 | EU 消耗 |
| --- | ---: |
| 待命、普通跟随 | 平均 46.296 / 秒 |
| 工作任务、追击和攻击 | 平均 185.185 / 秒 |
| 获得一次文字聊天许可 | 2000 |
| 成功下达一次手机机器人命令 | 200 |

正常 20 TPS 下，满电基础待命约 24 小时，持续工作或战斗约 6 小时；混合任务按实际活动累计，聊天/远程命令额外耗电仍保留。没有单次破坏/攻击的附加机器人电池扣费。没电暂停行动，货物格中的高级或核能充电宝可直接给已安装电池补电，无需拆电池；初级和中级电压不足。细节及加载时间边界见 [续航记录](robot-power-balance-2026-10-18.md)。

每台机器人有五次寿命。每次死亡先销毁电池槽内整块电池，再扣一次寿命；前四次返还带剩余寿命、装备和货物的娃娃，重新放置恢复生命值但仍需换电池。第五次死亡不再生成娃娃，其他装备和货物作为普通掉落物留在现场；消失诅咒遵循原版。世界环境与普通掉落物规则仍适用。

正常“收回娃娃”保留生命值、剩余寿命、电池 EU、装备及货物；背包满时拒绝收回，实体保持原位。正常收回不扣寿命。数据进入实体/娃娃 NBT，并在重新放置、存档读取时恢复；没有第二份机器人实体注册。

## 伐木、采矿与杀戮模式

“伐木”要求主手支持斧的采集动作；“采矿”要求镐的采集动作。任务以发出命令时的机器人位置为中心，搜索水平各六格、向下三格、向上五格的已加载区域，采集有外露面的原木或 `forge:ores` 矿石；不会无限扩展矿区，也不自动挖掉周围石墙、搭脚手架或强制加载区块。超高树干、被遮挡矿石或不可到达目标会跳过，改变任务位置后可重新下令。

机器人走到相邻可站立的位置，确认视线和 4.25 格操作距离后按实际工具速度采集。破坏使用主人身份的 FakePlayer 与原版 `ServerPlayerGameMode.destroyBlock`，保留 Forge 方块破坏事件、世界交互权限、`mobGriefing`、工具等级、附魔掉落和工具自身耐久/EU逻辑。仅收取本次破坏新生成的附近掉落物，已有地面物品不会被扫描吸走；满载暂停工作，未收下的掉落留在世界。特殊模组工具及领地保护组合仍需实机检查。

杀戮模式默认关闭，可独立开启或关闭。开启后寻找附近 16 格内敌对生物，使用装备武器攻击；排除玩家、友军与没有对机器人/主人产生敌意的中立生物。关闭立即清目标。它不授权攻击被动动物或其他玩家。

## 工业手机与网络

工业手机通过电子材料加工机（electronic_fabricator）制造：控制核心×1、工业 SSD×2、GPU×1、IC2 `ic2:uesc`×1、IC2 `ic2:complex_circuit`×2、高级充电宝×1；共六种输入，2400 tick、256 EU/t，总耗能 614,400 EU。配方及注册 ID 见[机器人工业配方记录](robot-industrial-recipes-2026-10-17.md)。IC2 储能组件的已有 EU 会随普通配方消耗，不会转移到手机；请先放空组件。

手持手机右键，自动加入附近有权限的交换机 Wi-Fi。无需 IP、密码或独立接入点。手机、机器人与目标设备须在同维度的已加载区块，且属于同一实际交换机/光纤组件；相同网络名本身不授予连接。跨区复用交换机之间的工业光纤，没有远程强制加载或物品传送。

- 手机查看机器人状态、电量、寿命、工具和位置；可发跟随、待命、伐木、采矿、杀戮开/关指令。
- 收回、换电池、装备与取货需要到机器人身边，防止将数据网络变成无线物流。
- 查看现有网络机器的 EU、转速、问题与运行状态。支持 `ControllableMachine` 的设备经现有控制服务器远程启停，保留服务器 AI 核心、启用开关与调试授权条件。
- 支持远程切换控制服务器启用状态、终端 AI 管理开关，以及修改交换机网络名；服务器/终端仍检查其原管理权限。
- 没有兼容控制接口的 IC2/Create/其他设备显示只读及原因，不声称能强制启停它们。交换机和适配器状态也可查看。
- 每条命令重新确认手持手机、真实网络组件、已加载目标与权限；掉线或电量不足时拒绝执行。机器人沿用原来的“只有放置者可管理”，工业方块保留 Owner/队伍/服务器权限规则。
- 手机音乐页可浏览、播放、暂停、切歌及控制歌单；播放与自动下一首要求玩家携带有电手机且处于 Wi-Fi 覆盖。请求经服务端 loopback 后，音乐元数据和音频分块只发给请求玩家。代码路径已接入，AstrBot music 路由尚未重载，6185 面板登录返回 HTTP 401，故尚未证明端到端播放或多人行为。

## 动画与声音

Astra 实现了八人行走、待命、工作挥臂、攻击、有限头部转向，接入原版手持和防具渲染层。原 R16 网格、图集和原 `.bbmodel` 未改。真实运行时姿态生成的 [动作总览](../art/robot-mcp-workspace/runtime-r16/animation/eight-character-animation-overview.png)、关键帧和 GIF 见 [动画交付记录](robot-r16-animation-2026-10-17.md)。当前为七个刚性部位，无肘膝弯曲或裙发物理；装备和动态碰撞尚待游戏内确认。

实现了可选语音桥。机器人页面默认语音关闭，开启后先显示文字；服务端只对最近且仍有效、已授权的机器人回复按需请求 TTS/RVC，并通过 Minecraft 音频分块发给请求玩家。客户端不需要 Python，也不向 8012 发请求。关闭页面、取消、新问题或关语音会取消旧播放；音量每 tick 按游戏主音量×语音音量更新。目前是源码接入状态，后端端点仍待重载，真实音频及多人验收未完成。

现有八角色训练数据是 RVC 音色，因此实际路线为“现有 GPT-SoVITS 基础 TTS → 对应 RVC”，不会另问内置 LLM。QQ 总语音开关、LLM 配置及 `.env` 保持原样。页面“桥接项目”提供 [QQ ChatRobot 项目链接](https://github.com/jiuxiansheng1111/qq-chat-robot)；本轮改动仅在本地，未上传。

具体启用步骤和环境记录见[语音桥文档](robot-voice-bridge-2026-10-17.md)。现有 QQ/AstrBot 进程尚未重载新的 music 路由，6185 管理面板登录返回 HTTP 401；用户完成正常插件重载后再验证服务端请求。保留现有 GPT-SoVITS/RVC 语音实现，不改原 LLM；服务端主机需运行可用的 ChatRobot/TTS 后端。
