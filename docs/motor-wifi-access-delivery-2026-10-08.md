# EU电动机、WiFi增幅器与服务器权限交付

日期：2026-10-08。此前终端机/界面与GitHub交付记录属于历史版本，本阶段状态以此文件为准。

## 已实现的源码与资源

- `ic2newera:eu_motor` 是一个能源设备，复用 Create 原生轴网与应力判定；不是第三台材料加工机。前端出轴，背面接 IC2 低压电缆；默认64 RPM，可选正负32/64/128 RPM及启停。红石信号停机。
- 三档固定消耗10/20/40 EU/t，提供1024/2048/4096 SU。标称128 SU/(EU/t)乘80%效率得到实际102.4 SU/(EU/t)。应力是Create的承载指标，此处为游戏平衡规则；没有引入现实机械功率单位。每包上限32 EU与总供给不同，128 RPM需要总供给40 EU/t。
- 10000 EU缓存；初启动需20刻额定电量。缺电停机后至少等待20刻并存足启动电量。存在上游外部动力时，本机退出供力并不耗EU；外部轴可能继续旋转。仅提供EU→转动输出。
- 电动机配方为3×3无序：安山合金×4、绝缘铜线×2、IC2电子电路×1、安山机壳×1、Create轴×1。物品ID已对照当前原始依赖JAR；复用现有材料。
- `ic2newera:wifi_amplifier` 为交换机升级物品，只有一个升级槽。覆盖水平40×40格：相对交换机dx,dz均为-20至19，上下各16格。未升级保持16格球形。光纤优先，只传数据，不叠加，不加载额外区块。拆除交换机会掉落升级物品。
- 增幅器3×3无序配方：PCB×1、IC2电子电路×1、绝缘铜线×2、Create电子管×2、安山合金×3。两条新路线均进入唯一ProcessGraph（54条），生成配方、RecipeGuard、规划器与科技树共用；新增三个科技节点后共33个静态节点。
- 电动机方块与增幅器物品模型/贴图为原创程序绘制，生成脚本与索引在`art/`。电动机机壳在0..16标准方块范围，六方向状态齐全；动态半轴引用Create运行时资源，未复制第三方资产。

## 服务器三档权限

服务器界面右上方、AI助手旁有权限按钮；只有联机房主/绑定的专服服主可循环切换。所有玩家都可打开服务器查看设备状态，最多24台设备详情，可滚动及悬停查看全文。AI快照最多16台，增加耗电/转速等机器细节。

| 模式 | 可查看 | 可配置/规划/控制 |
| --- | --- | --- |
| 所有人查看（默认） | 全部玩家 | 房主/服主及其授权名单 |
| 所有人配置 | 全部玩家 | 全部玩家 |
| 仅房主配置 | 全部玩家 | 仅房主/服主，暂不采用授权名单 |

只有根权限房主/服主能切模式、授予和撤销权限。访问模式随每个服务器方块保存；服主与授权UUID随世界保存。普通OP、服务器方块放置者和队伍关系不自动获得工业服务器配置权。终端与交换机的原有库存/网络所有权规则独立保留。

局域网房主由Minecraft自动识别。专服控制台或等级4 RCON先执行：

```text
ic2newera bind_controller 在线玩家名
```

房主/服主或控制台管理授权，目标玩家需在线：

```text
/ic2newera grant_controller 玩家名
/ic2newera revoke_controller 玩家名
/ic2newera controller_status
```

界面权限持续同步，收回权限后配置控件隐藏。核心槽放入/取出、操作包、AI提案执行均在服务端实时重新校验。切换权限包还验证当前打开菜单、坐标和8格距离，普通玩家不能通过“全员配置”取得权限管理权。新网络协议为3，双方需要同一新版。

服务器可以显式启动/停止已接入适配器的电动机；自动控制器不因电动机缺电或轴网过载去移除动力源，电动机自身处理供电及红石状态。

## 人工验收

1. JEI确认两条新配方，放置电动机，前端接Create轴，背面接低压EU；观察三档转速、容量、固定耗电与Create过载。
2. 缺电、重新供电、红石开关、反转、外部源接入/移除、拆除与重进世界，确认无免费发力或反向发电。
3. 交换机装入/取出增幅器，核对dx/dz=-20、19为边界，20在外；角落仍连通，上下16格为边界。检查卸载区块不会被网络强行加载。
4. 两名玩家分别打开同一服务器，房主依次切三档。确认访客查看、配置、核心槽取放和权限即时撤销；访客及委托玩家不能切档或再授权。
5. 专服普通OP不能绑定；控制台绑定后服主可配置及授权。重启世界核对模式/服主/授权名单保存。
6. 全员配置不解锁别人的终端库存；AI提案在收回权限后拒绝。小窗口/全屏检查AI按钮、权限按钮、核心槽与提示无重叠。
